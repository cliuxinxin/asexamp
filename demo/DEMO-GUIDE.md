# TCG v2.5.13 演示指南

建议演示时使用 HITP 人工确认模式，先用本目录的小需求验证模型连接。常规启动：`python3 start.py`。前端已随 ZIP 构建，无需先安装 Node。

## 与 v2.5.11 的能力对照

| 要点 | v2.5.11 | v2.5.13 演示入口 |
|---|---|---|
| 澄清放到项目供复用 | 有手工项目记忆，但澄清只在当前会话 | 提交澄清默认保存到项目；项目记忆查看/取消共享，新会话复用原始引用 |
| 评审看到 step / expected result | 标题表格，需逐条展开 | 评审结果展示完整步骤与预期；其他用例可“展开全部步骤” |
| 更友好的 case 微调 | 选中后到聊天框输入修改要求，直接应用 | 选中 → AI 微调 → 快捷要求 → 预览字段/步骤前后变化 → 确认应用 |
| 只按场景估算数量 | 没有专用任务，问答可能给口头估算 | 直接在聊天框问“这些场景大概需要多少用例，只估算不生成”；聊天展示逐场景区间、理由、假设与合计 |
| 中间成果编辑及联动 | 可编辑最新数据，但历史入口不便；无场景联动 | 阶段记录打开最新版本编辑；修改场景后预览并同步对应的关联用例 |
| 过程中加入新资料 | 上传接口存在，当前任务不采用新文件 | 确认节点“补充资料并重新理解”；原成果保留，新任务处理新旧资料 |
| 场景/用例覆盖 | 有模型评审文字，没有完整关系视图 | 覆盖表展示需求→场景→用例、缺口、未关联用例、待同步状态 |
| Sample case 固化 Profile | 学习字段规范，不保存完整案例快照 | 可选择 1–5 条用例固定到 Profile，未来作为格式样例，可替换/清除 |
| 解释/总结已有 case | 支持问答，但连续追问的目标可能选错 | 用例卡片“解释选中用例”或“总结用例”，绑定明确成果版本；证据问答也绑定当前打开成果 |

## 主演示路线

### 1. 建项目，生成并共享澄清

1. 创建项目“演示·员工门户”。选择 HITP 人工关键节点。
2. 上传 `01-login-requirement.md`，用途选择“主要需求”。选择“生成用例”，使用自动填好的提示词发送。
3. 等待澄清。展示每个问题的建议；点击“采用此答案”或“采用全部建议”，对应问题提示会收起。
4. 为了后续演示一致，在答案区明确填写：连续错误 **5 次**、锁定 **10 分钟**、**不允许管理员人工解锁**。建议可以修改，采用本身不提交。
5. 保持“保存到项目”选项勾选，再提交。打开“项目记忆”，展示刚才的问题和已确认答案。
6. 用第二个浏览器打开同一服务，选择同一个项目；打开项目记忆，看到同一份澄清。新建会话再次使用该项目资料时，新任务会载入这些澄清；不同项目不会载入。

模型可能合并问题或使用不同措辞；看实际问题内容，不依赖固定问题编号。项目共享采用的是你提交后的答案，而不是未经确认的模型建议。

### 2. 直接聊天估算，不选任务

1. 确认需求理解，等待场景确认。保持上一次任务选择不动，不点击估算按钮。
2. 在底部聊天输入框直接发送：

   > 根据当前这些场景，估算需要多少条测试用例，分别给出数量范围和理由。先不要生成用例。

3. 展示聊天中的估算表：来源版本、逐场景最小/最大数量、理由、假设及合计。
4. 继续在聊天框问“只估第二、第三个场景，不生成”，核对表中实际场景编号与顺序。如果只有一个场景，改用实际存在的编号。
5. 继续问“那只算异常情况呢？”，核对仍是估算并遵循最新范围。模型可能给出不同区间，核对目标、理由及业务范围，不依赖固定数字。
6. 展示仍停在原场景确认节点，场景版本不变，没有新的用例成果。只有点击确认场景才继续生成；实际生成数不受估算区间强制限制。

已有多套场景时，打开要估算的成果后直接问，或在消息中写明成果编号。找不到明确目标时系统会问清楚，不自动生成。没有场景的新对话直接问估算，会说明缺少场景。更多检查见 `CHAT-ESTIMATE-TEST.md`。

### 3. 评审时展示细节

1. 生成完成后选择“评审当前用例”，或选择“评审用例”任务发送。
2. 查看评审结果的步骤明细。如果当前显示紧凑表格，点击“展开全部步骤”。
3. 展示同一条用例的前置条件、描述、操作步骤、对应预期、类型和优先级。
4. 在阶段执行记录中分别打开“生成时的用例草稿”和“评审结果”，可比较当时的版本。

### 4. 对一条 case 做友好的微调

1. 勾选一条用例，点击“AI 微调选中 1 条”。
2. 点击“步骤更清楚”，或输入：

   > 只优化选中用例的步骤和预期结果，把每一步操作写清楚。保留编号、需求引用和所有人工填写内容，不新增业务规则。

3. 点击“预览修改”。展示修改前/后字段，尤其操作与预期；此时原成果版本尚未改变。
4. 点击“确认应用修改”。展示新版本及历史版本，核对其他用例保持不变。
5. 需要手动修正时，用“编辑”进入表单；复杂自定义字段可在 JSON 视图编辑。

### 5. 修改中间场景并同步关联用例

1. 在聊天的阶段成果中展开“测试场景”，点击“打开最新版本并编辑”。历史阶段快照保持原样。
2. 选择一个“失败计数/锁定”场景，手动编辑其描述，例如补充：

   > 还应验证成功登录后失败计数清零；下一次密码错误从第一次失败开始计数。

   这项规则已在原需求中，便于展示有依据的联动。保留该场景 ID 和需求引用，保存新版本。
3. 查看覆盖表里的待同步提示，点击“同步关联用例”。新生成的用例默认按保存的来源关系关联。
4. 预览对应场景的用例变化；可勾选场景限定同步范围。确认应用后，再看用例版本和覆盖表。
5. 未选中场景的用例保持原样；部分同步只清除对应场景的待同步状态。

旧版本产生的成果可能没有保存上游关系，需要在同步弹窗明确选择同一对话内的旧用例成果。系统不会仅因两个场景编号相同就自动认定有关联。

需求理解也可打开最新版本修改摘要、业务图或条目。之后使用“继续生成场景”让新一轮读取修改后的理解。现有联动操作专门处理“场景→关联用例”；不会无声地重写整个项目。运行中请先到确认节点或结束任务，再修改成果。

### 6. 中途加入新资料

1. 另建一次 HITP 生成会话，使用初始需求，停在需求理解或场景确认。
2. 点击“补充资料”打开“补充资料并重新理解”弹窗，上传 `02-login-change.md`；也可粘贴其中内容。
3. 已经通过主输入区上传的文件，可在该弹窗勾选。主输入区在运行期间上传，只保存附件，不会直接改动进行中的模型请求。
4. 点击“应用补充，重新理解”。展示旧任务和旧成果仍存在，新任务沿用原目标、Profile 和模式。
5. 在新的需求理解、场景和用例中查找“管理员强制下线”和“普通员工越权请求”。打开引用，可看到补充资料。

这一步会重新处理需求，是一次新旧资料合并后的后继任务。它与步骤 5 的“只同步关联用例”不同，演示时明确说明操作范围。

已生成成果也可接入新资料：先上传补充文件，再在“AI 微调”或“同步关联用例”弹窗点击“添加本次补充资料”，主动勾选后预览。此方式只处理指定成果，不会重跑整条生成流程。

### 7. 展示覆盖与缺口

1. 在场景或用例卡片打开“覆盖”区域，展示需求、场景和用例的计数。
2. 指出需求行关联了哪些场景、这些场景有多少用例；展开具体 ID。
3. 为演示缺口，可在场景成果手动新增一条有原始需求引用和 requirement_ids 的场景，先不生成用例。覆盖表应显示这条场景没有用例。
4. 对新增场景执行“同步关联用例”，检查预览的新用例，应用后刷新覆盖表。
5. 如存在多套用例成果，选择其中一个分支核查，避免把重复生成的案例数量叠加。

覆盖展示是引用关系统计。它能发现未关联、缺少用例和版本未同步；不代表测试已经执行、通过，也不保证业务条件已经穷尽。

### 8. 固定 sample case 到 Profile

1. 勾选 1–5 条认可写法的用例，点击“保存为项目样例”。
2. 选择本项目要保存的 Profile，确认保存。此操作替换该 Profile 当前固定样例。
3. 打开 Profile 编辑器，查看样例内容；展示可以清除，不是永久锁死。
4. 用该 Profile 新建生成任务，未来生成/评审会收到这些格式样例。

建议固化少量代表性样例，用于步骤写法、描述粒度和术语风格。样例快照去掉 refs、scenario_id 等业务关联；旧业务规则不会自动成为新需求。仅学习 Excel 列名时不必固定案例，可直接上传 `03-case-format.csv` 学习模板。

### 9. 解释或总结已经生成好的用例

1. 回到用例成果，不选行时点“总结用例”。默认要求按业务内容和验证重点总结。
2. 勾选一条或几条，再点“解释选中用例”。例如输入：

   > 向产品经理解释这些用例分别验证什么，主要步骤和预期是什么；指出当前内容中的未明确点，不修改用例。

3. 展示说明生成后，原用例条数和版本不变。
4. 也可打开指定用例成果，切换“证据问答”继续提问；连续追问仍使用当前打开的用例，不会把上一条回答当作用例目标。

## 同项目多人访问的演示部署

两个人必须访问同一服务地址及数据目录。假设演示服务器内网 IP 为 `192.168.1.20`（替换成实际 IP）：

```bash
python3 start.py --host 0.0.0.0 --allowed-hosts 192.168.1.20 --no-browser
```

两台电脑都打开 `http://192.168.1.20:8000`，选择同一项目。默认仍只监听本机。项目当前没有成员账号/角色权限体系；此处演示的是同一内网服务里的项目数据复用，不是跨独立安装同步或成员权限管理。

## 演示前检查

- 在模型设置中保存服务地址、模型名和必要凭据，测试连接。
- 使用实际模型的上下文容量设置；本演示使用小资料，避免容量对结果的干扰。
- 首次用目标模型走一遍上述主路线；本次开发验证使用可控模型响应，未连接你的真实模型。
- 普通聊天会先调用轻量意图识别；估算、解释、AI 微调预览、联动预览会调用模型；手动编辑、查看覆盖、保存共享澄清、固定样例无需额外模型调用。
