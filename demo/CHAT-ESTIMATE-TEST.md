# TCG v2.5.13 直接聊天估算验收

这是一套供真实模型执行的验收步骤。开发中的可控响应测试不等于已在你的模型上通过。

使用现有场景或按 `ALL-SCENARIOS-TEST.md` 走到场景确认。在普通聊天框输入以下内容，不选估算任务、不点估算按钮；上一项“生成用例”可以保持不动。

| 步骤 | 直接输入 | 核对 |
|---|---|---|
| 1 | 根据当前这些场景，估算需要多少条测试用例，分别给数量范围和理由。先不要生成用例。 | 聊天出现逐场景表和总区间，注明来源版本；没有生成 case |
| 2 | 只估第二、第三个场景，不生成。 | 表中实际 ID 对应当前场景的第 2、3 项；数量仅合计这两项 |
| 3 | 那只算异常情况呢？ | 延续刚才场景范围，理由围绕异常情况；仍是估算 |
| 4 | 这些数量为什么给范围，而不是一个确定数字？ | 普通解释，不误生成、不提交确认 |
| 5 | 根据当前这些场景，再估一次包括正常、异常和边界的数量。 | 新消息显示本次范围和合计，旧估算仍可查看 |

场景不足三条时，用真实存在的场景编号替换第 2 步。

每次估算前后对比：等待状态及确认节点相同，场景版本相同，case 成果数量不变。合计等于表中各行最小值/最大值之和。模型数字可以变化，不把估算当作生成配额。

完成用例生成后，打开这套用例的成果再问“这些用例对应的场景，如果只考虑正常流程，大概需要多少条用例？先不生成”，核对估算来源是其关联的场景。要问现有条数可直接问“这里已经有多少条用例？”——应回答当前成果统计，不能另做设计工作量估算。

边界检查使用单独会话：

- 没有场景时问“帮我估算用例数量”：说明还缺场景，不自动发起生成。
- 多套场景且没有明确目标时：要求指定成果。回复实际成果编号，或打开目标后重新问，应绑定该版本。
- 输入不存在的场景编号：提示核对范围，不能默默估算全部。
- “不要估算，直接生成用例”：不能被识别成估算；有待确认任务时仍需按原确认入口推进。为了保留主验收现场，放到额外的已完成会话测试。
- 模型请求失败时：显示错误，问题草稿保留，不启动生成任务。

若输入框当前标有“修改：某成果”或主动勾选了“正文作为需求”，先退出该明确操作模式；它们是专门的编辑/需求输入，不是普通聊天。
