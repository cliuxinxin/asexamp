## v2.5.8 任务提示、建议答案与场景模板

- 选择“学习模板”等具体任务后，聊天输入框会填入可直接发送、也可修改的提示词。切换任务只替换空白或上一条默认提示，不覆盖已编辑的草稿。
- HITP 需求澄清可显示建议答案、依据与“原文支持 / 待确认假设”标识。点击“采用此答案”或“采用全部建议”填入回答后，检查并点击“提交并继续”；不会自动提交。没有有效建议时仍可手动回答。
- 测试场景结果支持“导出 Excel”，可导出全部或选中条目。导出使用已保存的场景，不调用模型。
- 学习模板可识别场景模板、用例模板或两者；建议中的两套配置互不覆盖，仍由用户选择更新 Profile、新建 Profile 或仅下次使用。
- Profile 新增独立的场景工作表名、文件名、列顺序和字段定义。旧 Profile 无需迁移，场景默认导出编号、标题、描述、优先级、需求编号与证据引用。
- 升级时保留原 `data` 目录和模型配置。已保存的分析不会凭空补出建议答案；新生成的分析按新契约提供可选建议。

定向验证记录见 `docs/VALIDATION-v2.5.8.md`。

## 启动

1. 解压到新目录，复制 `.env.example` 为 `.env` 并填写原有模型配置；也可通过界面配置。
2. 运行 `python3 start.py`，Windows 可用 `py -3.12 start.py`。首次安装依赖需要联网，常规启动不需要 Node.js。
3. 打开 http://127.0.0.1:8000 ，**新建会话测试本版流程**。已有数据保留，但旧的进行中任务不会自动改写为新版检查点。

## 怎么操作

- 上传需求：文件用途选择“需求正文”或“自动识别”。如果文件被标成模板且没有其他需求，系统会等待你勾选“本轮作为需求使用”，然后继续原任务。
- 粘贴需求：勾选“正文作为需求”再发送。未勾选时作为普通对话处理；生成任务缺少需求会显示补充入口，预填当前消息供确认。
- 自动识别：识别本次是在生成、分析、修改、评审、学习模板还是问答。也可直接选择任务按钮。
- Auto：理解 → 场景 → 用例 → AI 评审 → AI 总结。
- HITP：在澄清、理解与方案、场景确认节点等待。检查和修改后点击确认按钮。
- 暂停期间问问题：选择“证据问答”发送，不推进确认。澄清阶段直接发送文字则作为澄清答案。
- 从分析继续场景、从场景继续用例：使用结果下方的继续按钮，复用当前结果。
- 修改：点击“让 AI 修改此结果”，输入修改要求；也支持表单编辑及历史版本。
- 评审：点击“评审当前用例”，评审已有结果并保存修订。
- Profile / Excel：顶部入口可修改颗粒度、深度、规则、Sheet、文件名、列名和列顺序；模板学习只提出建议，由你选择更新、新建或仅下次使用。

## 实际结果与恢复

回答只作为对话展示，不再计为一条用例。生成结果总结基于真实产物及评审报告；总结服务暂不可用时仍保留已生成的结果，并明确说明。

每个人工暂停点是独立节点；来源写入和应用澄清在另一节点完成。失败重试复用已保存阶段，不重复提交旧澄清指令。校验修复保留合法行，只修复问题内容；持续失败仍暂停，不把无效结果当成功。

普通自动生成约五次业务模型调用：理解、场景、用例、评审、总结；自动意图识别额外一次。这些是不同阶段，不是文档分组。

```dotenv
TCG_MODEL_CONTEXT_TOKENS=0
TCG_OUTPUT_TOKENS=8192
TCG_SEND_OUTPUT_LIMIT=false
```

0 表示不设本地 token 上限，服务端决定模型容量；需要提前分组时显式填写实际容量。文件解析和单请求体积保护仍保留。默认兼容网关继续仅发送 model/messages，不要求 tools 或 embedding。

## v2.5.3 失败步骤日志与 JSON 定位

- 失败任务卡片直接显示“下载失败步骤日志”，每个失败调用旁也有“下载本次错误”。下载 UTF-8 Markdown，最多 64 KiB；只选失败步骤最近 6 次调用。
- 记录请求时间、模型、耗时、结束原因、输出大小、JSON 行列位置、错误附近原文、实际系统提示词、格式修复要求及字段校验错误。长内容明确标记节选，不带完整需求、历史产物、检查点或认证请求头。
- 完整诊断包保留在运行详情。下载日志只读取已有记录，不运行模型、不重做需求理解；保留原数据目录即可为已有失败任务导出，旧版没有保存的内容无法补回。
- 提示词明确双引号、反斜杠、换行和 Mermaid 字符串的转义规则，提供合法 mindmap JSON 示例。解析错误定位到原始文本，不再一律要求换模型；修复兼容接口响应损坏时错误处理引用未定义变量的问题。
- 提示词约束不是服务端结构化解码保证。仅凭错误摘要无法确认真实模型的故障原因，需查看上述小日志。

## v2.5.4 自动过程、模板定义与评审修复

- 自动模式逐阶段发布需求理解、场景、用例草稿、评审摘要。每条可展开该阶段保存的成果版本，包含业务图；完成后的执行记录默认展开。阶段展示使用已有产物，不额外调用模型，不增加人工暂停。重试同一阶段不会重复发布消息。
- 生成、评审接收本轮 Profile 和附件模板正文。模板作为 format_references 独立传入，不充当业务需求引用。需求理解阶段采用范围与业务关注点，不使用 Excel 列映射。
- Profile 的每列可编辑 definition（字段定义）。用例结果显示“本轮模板与字段定义”，列明配置、模板名、写作规则和导出列。上传模板仅提供格式参考；如要改变导出列，使用模板学习建议并应用到 Profile，或直接编辑列映射。
- 对 finish_reason=stop 且仅在末尾缺少容器结束符、已有嵌套值完整的 JSON，验证后仅补齐括号，不重问模型；原始返回保留。字符串、数值或字段值未结束时不猜测补全。需求理解若混入用例步骤等字段，先定向修正，再进入场景阶段。
- 评审允许有需求引用、具体理由的范围排除。report.scenario_exclusions 显式列出被排除场景，不再强制给排除项保留虚假用例；无依据的覆盖丢失仍会要求修复。
- 字段校验错误绑定具体调用，小日志会显示该调用被拒绝的原因，即使任务仍在 running 或后来已完成。旧记录可按节点及时间关联补查。

详细变更、日志解读及本地验证范围见 docs/FEEDBACK_V254.md。保留原数据目录后启动新版；以前自动执行未发布的中间成果不会补造聊天消息，但原执行记录仍可回看。

## v2.5.5 用例描述补全

修复模板有“用例描述”列，但生成内容未包含该字段，导出直接写空的问题。

- 生成提示词包含 description 示例，并明确所选模板要求该字段时必须填写；仍漏填则只请求补全缺失描述，保持其余用例字段与 ID 不变。评审新增或清空描述时也执行相同检查。
- 支持 description、case_description、test_case_description、case_desc、test_case_desc、用例描述、测试用例描述等常见字段名（忽略英文大小写、空格、连字符）。列标题保持用户设置。
- 已有用例：打开“导出 Excel”，选择含描述列的 Profile，再点“补全用例描述”。完成后重新导出。不重新理解需求、不生成场景、不重做整套用例；已有非空描述保留。
- 导出前检查描述，缺失时提示补全，避免再次静默导出空列。不用标题复制代替描述，也不会由下载 GET 请求触发模型。

此修复针对用例描述字段，其他自定义列的业务含义仍按 Profile 定义处理。


## v2.5.6 按模板逐列生成与补全

本版把 v2.5.5 的“用例描述”专用补全升级为模板字段契约。学习模板、Profile 列定义、生成、评审、对话修改和导出共用所选列的定义，支持任意自定义用例字段，不再仅检查 description。

- Profile 中每列可设置定义和填写方式：AI 根据需求生成、从步骤自动汇总、人工填写、固定默认值。AI 列还可选择导出前必填或允许留空；默认值支持空字符串、数字 0 和布尔 false（复杂类型可在 JSON 配置中设置）。
- 模板学习提出上述列配置，用户应用后才生效。步骤与预期使用内部 steps 数组导出；description 的历史别名继续兼容。内部来源字段不作为 Excel 用例列。
- AI 首次生成时收到所有列定义。若遗漏必填自定义字段，一次请求补齐当前用例的全部缺项，仅当内容超过容量才分组；不重新生成需求理解、场景或已有用例。
- 实际执行结果、执行人等人工列不会由生成或评审编造；保留人工已有值。业务依据不足时保存具体待补充原因，正常完成当前任务，不按 JSON 错误重试。
- 导出窗口逐项列出缺失字段与原因，可“补全模板字段”或“填写缺失字段”。缺失 AI 必填字段时拦截空列导出；人工列及可选列允许留空。修改 Profile 或切换导出模板后，检查所选模板与所选用例的实际内容。
- 已有结果使用生成时的配置快照；选用新的导出 Profile 不会静默替换旧快照。补全操作保留稳定 ID、已有字段、未选中用例与版本记录。

此处的通用模板指列名、顺序、字段定义及填写方式；不意味着原 Excel 中任意公式、合并单元格、宏或复杂版式都会被复制。AI 内容仍需结合实际业务复核。

## v2.5.7 人工确认前的 AI 修改

- 修复 HITP 确认节点调用 AI 修改时，被通用运行状态检查误判为“过期结果”的问题。只有持有本次私有编辑令牌的等待任务可继续写入本次模型缓存；取消或状态变化后仍会拒绝迟到结果。
- AI 修改期间保持原来的“理解确认”或“场景确认”节点，不重新分析需求，也不提前生成下一阶段。修改保存为 Artifact 新版本后，用户再确认；后续场景或用例使用最新版本。
- 前端在发送修改后立即禁用确认按钮，服务端也会拒绝并发确认且不改变任务状态。刷新页面后仍可通过公开的 `edit_in_progress` 状态看到锁定，私有编辑令牌不会返回浏览器。
- 执行过程中新增“AI 正在修改当前确认结果”和“AI 修改已保存，仍等待确认”的事件，方便定位确认与修改的先后顺序。
