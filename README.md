# TCG Case Agent 3.0.13

通过对话理解需求、生成场景与用例、评审、修改和导出；保留红色对话布局、输入框附近的选项和按需打开的成果表格。Chat Agent 使用原生 Tool Calling，后台 LangGraph 使用独立检查点和人工确认节点。

本版增加 Supervisor 规划与分发：例如“将这些用例的前置条件改为已登录，然后导出 Excel”，先规划修改和导出，展示修改预览；接受后继续导出修改后的版本。计划跨消息保存，等待时可以提问，拒绝则取消后续步骤。每一步只提供所属能力的工具；后台生成仍逐步人工确认。简单“同意”直接处理当前确认，不额外调用规划模型。聊天中的“本次安排”卡片展示实际执行状态。

本版将修改预览放进 AI 消息卡片，原地接受或拒绝；场景、用例均可打开表格手动编辑或通过 AI 修改。独立条目的上游关联显示 N/A，不创建虚拟需求。Human 主流程确认需求理解、场景和评审建议；生成用例后直接评审，确认建议后才应用用例修改。用例列变更先修改当前数据，再让用户查看并确认 Profile 差异；同一请求中的导出会在确认后自动完成。

生成结果校验失败时：首次生成后最多自动修复 **3 次**，每次带上具体错误和上次结果。仍不合格时，在对话中提供**待核对草稿**，可查看条目、各轮输出及先前已通过的分批内容。草稿不冒充已完成成果、不自动进入下一阶段。删除已脱离当前入口的历史文件，保留运行、数据兼容与当前测试。

明确要求时可以跳过场景，直接从已确认需求生成用例；只要草稿时不评审。澄清互斥选项放在每个问题下，点击仅提交本题。侧栏追溯矩阵可查看本会话或全项目的真实关联、缺口和待同步状态。主要提示词位于 `backend/tcg/prompts/`，可编辑 YAML，下一次模型调用生效。

## 启动

需要 Python 3.11 或更新版本，推荐 Python 3.12。解压到新目录后运行：

```bash
python3 start.py
```

Windows 可使用 `py -3.12 start.py`。首次安装依赖需要联网；包内有前端构建文件，日常启动不需要 Node.js。

模型地址、名称和认证通过设置页面或 `.env.example` 配置。完整 Azure 环境配置优先采用 Azure；原网关及 Ollama 保留。模型和网关需要支持原生 Tool Calling，连接测试会实际验证工具调用。

上下文容量交给模型服务器控制，客户端不预先按 Token 拒绝请求。可拆分的业务批次只在服务器明确超限后拆分；聊天超限保留已完成操作，不重放整个回合。输出预算单独配置。

## 升级

停止旧服务并备份原数据目录，再使用新版启动：

```bash
python3 start.py --data-dir /path/to/existing/data
```

项目、资料、Profile、成果版本和历史消息保留。旧任务若无法可靠恢复确认位置，会保留成果并提示重新开始。同项目共享需使用同一个后端服务；本版没有新增成员权限系统。
