# Supervisor Planner：跨确认节点的连续任务

用户授权在 v3.0.11 上加入规划与监督分发，示例是“把选中用例前置条件改为已登录，然后直接导出 Excel”。现有 Chat Agent 已支持多轮工具调用；本次补上任务跨消息和确认节点的持久化，以及每步能力约束。

## 执行边界

- 非简单控制消息先通过原生 `submit_execution_plan` 工具提交能力步骤。Planner 只拆分用户公开目标，不返回或执行代码，不修改数据库。
- 每个步骤由专门的工具子集执行。能力包括读取解释、估算、成果修改、用例列、Profile、模板学习、项目知识、Pipeline 启动/控制、评审修改、样例、字段补全和导出。
- 步骤不允许计划未来的“自动同意”。需要人工确认由真实工具的 `needs_confirmation` 回执决定；原有 prompt ID 和版本约束继续生效。
- 明确的当前确认、拒绝以及已绑定澄清按钮直接执行其唯一控制操作，不经过 Planner。含修改意见的复合句不能被当作简单同意。
- 其他自然语言确认使用仅首步可选的 `current_control`，绑定规划前已有的唯一提示；按该对象提供接受/拒绝工具，不能批准本轮刚产生的预览或未来的流程节点。

## 持久化与续跑

计划记录步骤、目标编号/版本、选择范围、当前等待对象、结果收据。资料正文继续保存在来源与成果中，不复制进计划。

“修改→导出”在预览准备后暂停；接受精确预览后更新计划绑定为本次保存的新版本，继续导出原选择。提问不会触发尾部动作；拒绝取消依赖该修改的后续动作。修改预览过期或版本被其他操作改变时，必须停止并说明，不能导出错误版本。

服务恢复时保留等待队列和已完成步骤。动作成功的收据用于去重，不根据模型一句“完成了”认定任务成功。生成管线仍使用原来的 LangGraph 与人工确认；队列只等待其真实完成，不能暗中替用户确认各环节。

## 界面

在现有 AI 消息内增加紧凑“本次安排”卡片，展示公开目标及步骤状态。修改仍使用原来的内联 Diff 接受/拒绝，Profile 保留现有确认入口；不新增另一套确认按钮。

## 验收

使用真实 HTTP、SQLite、原生 Tool Calling 消息与实际 Excel 单元格验证：修改选中项→等待→提问→接受→准确版本导出；拒绝不修改不导出；重启恢复；重复确认不重复写入；过期预览不触发尾部；多能力执行只获得所属工具。模型使用受控响应，真实部署需要用户演示前预跑。
