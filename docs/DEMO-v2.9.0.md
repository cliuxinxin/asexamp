# TCG v2.9.0：一段连续对话验证全部要点

本演示从一个新项目、一个 Human 任务开始，持续使用同一组需求、场景和用例。除了上传文件、查看表格和勾选范围，后续操作直接通过聊天完成。无需切换“估算”“修改”“总结”等任务选项。

## 准备（约 3 分钟）

1. 停止旧服务并备份原 `data` 目录。解压新版，用 Python 3.12 运行 `python3 start.py`；Windows 可用 `py -3.12 start.py`。保留原数据目录和模型设置。首次安装依赖需要联网，包内已有前端构建产物。
2. 创建一个全新演示项目，避免以前确认过的锁定规则消除本次澄清。连接你的模型，在设置中填入服务实际支持的上下文窗口和输出容量。
3. 打开 **任务设置 → 执行方式 → Human · 逐步确认**。任务开始后执行方式随该任务固定；不要用切换输入框设置来改变已运行任务。
4. 准备包内 `examples/conversation-v290/` 的三个 Markdown 文件。两份模板沿用 `examples/conversation-v260/scenario-template.xlsx`、`case-template.xlsx`。

原版红色用于主要按钮与选中状态，页面保留白色侧栏和浅灰背景。对话区较宽，输入框开始时只有两行；表格可局部横向滚动、展开或进入专注查看。先使用桌面浏览器预跑一遍：真实模型的措辞、编号和数量会不同，下面用勾选或实际编号指定对象。

## 连续演示

“应看到”用于验收保存结果与流程状态。若系统确实缺少对象，应在当前对话补充该对象，再继续同一步。

| 步骤 | 操作或可复制的聊天内容 | 应看到的结果 |
|---|---|---|
| 1 | 点击开始页 **学习模板**，查看输入框；先不要发送，清除这段提示。 | 已填入可编辑的具体提示。已有手写内容不会被快捷任务覆盖。输入框没有铺满页面。 |
| 2 | 上传 `login-requirements.md`，用途为需求正文。发送：**根据这份登录需求生成场景和用例，每个关键阶段都等我确认；缺失规则先向我澄清。** | 先理解需求；锁定时长/解锁方式需要澄清。还没有用例。 |
| 3 | 若建议正确，点击 **采用此答案**；本演示推荐直接说：**我确认：连续失败五次后锁定十分钟，期满自动解锁。请采用这个答案并保存到项目，先不要生成场景。** | 已回答的问题消失；答案保存为项目已确认规则并更新理解。仍未批准理解；未回答的问题继续保留。 |
| 4 | 打开 **已确认规则**，或说：**列出本项目已确认的锁定规则和来源。** | 显示十分钟、来源对话、确认时间与适用范围。若只是暂定，可以使用“先按假设使用”，它不会成为共享事实。 |
| 5 | 说：**确认更新后的需求理解，生成场景后等我确认。** | 进入场景生成，再停在场景确认。理解条目本身已写入十分钟规则。 |
| 6 | 展开一条场景的关联需求。 | 同一行可看到需求编号、标题、原内容和证据；不需要另开覆盖页面。缺关联时明确显示缺口。 |
| 7 | 清除勾选范围，直接问：**这些场景大概要多少条 case？只给逐场景区间、理由和假设，不生成用例，也不要继续。** | 对话给出估算；用例数量仍为零，场景版本不变，仍在场景确认。 |
| 8 | 勾选“有效凭证登录”场景，说：**解释选中场景为什么这样设计，以及它对应哪条需求。不要修改。** | 对话解释选中对象和依据；不会继续任务。输入框上方显示已选范围。 |
| 9 | 继续选中这条场景，说：**把选中场景标题改为“使用注册账号的有效凭证完成登录”，描述和其他场景保持不变，先别继续。** | 保存场景新版本；只有该标题改变，仍等待确认。展开旧消息能看到旧版本，不会把当前确认对象换回旧版。 |
| 10 | 清除勾选范围，说：**确认当前全部场景，生成用例草稿后等我确认。** | 用例草稿使用最新场景；停在草稿确认，尚未自动完成评审。 |
| 11 | 查看一条用例，展开步骤与上游关系。 | 表格显示前置条件、成对的 step / expected result、主场景和需求；展开可看完整步骤、自定义字段及证据。 |
| 12 | 勾选有效登录用例，说：**只把选中用例中执行登录的步骤动作改为“输入已注册账号的有效凭证并提交登录”，预期结果和其他步骤保持不变；先给我看修改预览。** | 对话显示局部差异。检查后点击应用，或说“采用这次预览”。保存后仍停在草稿确认。可继续微调；修改期间确认按钮不可用。 |
| 13 | 上传 `login-audit-supplement.md` 和 `unadopted-export-note.md`，用途为补充/变更。暂不发更新要求。 | 资料已保存，但当前理解、场景、用例版本不变；仅上传文件不阻止确认当前成果。 |
| 14 | 保持选中有效登录用例，说：**只采用 login-audit-supplement.md，为选中用例增加成功登录后检查账号和设备标识审计记录的步骤。只改这条 case，先不改需求理解和场景，也不评审。不要采用另一份导出审计资料。** | 只更新该用例；新步骤引用登录审计资料。理解和场景保持原版，表内提示上游尚未同步。不会混入九十天保留规则。 |
| 15 | 打开需求理解，勾选有效登录需求，说：**把刚才的登录审计补充也纳入选中需求，并同步这个需求关联的场景，保留无关内容。先不要继续主流程。** | 对应理解和场景产生新版本；已有用例若受影响，会在其行内显示待同步。需要同步哪些对象由实际关联决定。 |
| 16 | 打开用例、清除勾选，说：**按更新后的场景同步受影响的已有用例，保留其他用例、人工填写字段和现有编号，完成后仍等我确认草稿。** | 只更新受影响用例；已经符合的内容保留，相关过期状态消除。如果只选其中一条，同场景的其他未同步用例仍显示待同步。 |
| 17 | 说：**确认当前最新用例草稿，开始 AI 评审，评审完成后等我确认。** | 开始一次评审；之后停在评审结果确认。表格保留步骤与预期，显示实际评审发现和修改项。 |
| 18 | 说：**总结这次评审发现的问题，并解释有效登录用例的验证目的。不要修改，也不要完成任务。** | 给出解释/总结，仍停在最终确认。设计评审不会被描述为已经执行测试。 |
| 19 | 说：**确认当前评审后的结果，完成这个任务。** | 主任务完成；各阶段成果、旧版本和执行记录仍可查看。 |
| 20 | 勾选 1–2 条认可的用例，说：**把选中的用例保存为当前项目 Profile 的格式样例，供后续参考写法；不要把里面的业务规则当成其他需求。** | Profile 保存所选版本的样例。之后修改原用例不会悄悄改动这个快照；需要时重新明确固定样例。 |
| 21 | 上传两份 Excel 模板，用途为模板/格式样例。说：**学习 scenario-template.xlsx 和 case-template.xlsx，分别提取场景和用例模板，先展示建议。** 检查后说：**将这两份模板建议应用到当前 Profile，保留人工执行字段的填写方式。** | 两套列定义分别保存，不互相覆盖；学习不会生成新的需求、场景或用例。 |
| 22 | 清除选择，说：**按当前 Profile 分别导出全部场景和用例为 Excel。** | 两个下载文件；场景模板与用例模板各自生效。若新的必填设计列尚缺内容，可在导出窗口查看缺项并只补全缺失字段。 |
| 23 | 说：**用面向业务人员的语言总结目前全部用例覆盖了什么，还有哪些限制。不要改动。** | 完成后仍能总结已有用例；版本和数量不变。关联统计不等于语义覆盖已被证明。 |

## 同项目复用与自动模式对照

在同一项目新建对话，问：**本项目已经确认连续失败五次后锁定多久？请说明来源。** 应回答十分钟，并引用之前确认的项目资料。换成同一服务上的另一个浏览器也应能读取同项目规则；本版没有新增成员账号和权限管理。

在这个新对话上传原始需求，选择 **Auto · 自动完成**，发送：**按本项目已确认的规则自动完成需求理解、场景、用例和评审。** 正常路径自动完成相同阶段，不出现人工模式的四个确认停点。若有无法确定的业务冲突，系统仍应明确提问，不编造答案。

如果要展示运行中修改，发送：**等当前步骤保存后，把后续测试范围限制为登录模块，继续完成原任务。** 修改在安全边界处理；原 Auto 目标保留。若说“先停下，等我确认”，任务应保持等待。不要通过重复点击继续来催促正在执行的修改。

## 演示时判断成功的七个信号

1. 人工模式四个确认点都存在：理解、场景、用例草稿、评审后结果。
2. 估算、解释、总结期间没有新增用例，也没有隐式确认。
3. 已答问题收起，项目规则可复用；暂定假设不外传为已确认规则。
4. 修改选中条目后，稳定 ID、无关行和人工字段保留；确认使用最新版本。
5. 新文档只有在明确采用后才影响指定成果，直接改下游会如实提示上游差异。
6. 场景和用例行内能看到真实上游关系、缺口及待同步状态；历史关系读取当时版本。
7. 场景和用例分别按模板导出；固定样例只指导格式；完成后可以继续解释和总结。

程序验收使用真实 HTTP、SQLite、LangGraph 和受控模型响应，验证的是这些操作契约。你的实际模型对自由文本的判断和最终浏览器视觉效果仍需现场预跑；本次环境的浏览器访问本地页面被阻止，没有声称完成视觉验收。
