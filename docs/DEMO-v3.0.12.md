# Supervisor 连续任务演示

使用同一会话完成以下操作。先在设置中测试模型连接，模型必须支持原生 Tool Calling。已有用例可从第 2 步开始；保留原红色聊天布局，成果按需打开。

## 1. 生成与人工确认

上传一份小需求，选择逐步确认模式，发送：

> 根据上传需求生成测试用例，包含评审，确认完成后导出 Excel。

预期“本次安排”包含生成和导出。依次处理澄清、确认需求理解、确认场景。用例生成后直接产生评审建议，查看后回复“同意”。所有人工节点都应停留；最后确认评审后才完成用例并导出，不需要再说一次“导出”。

## 2. 一句话修改后导出

打开用例表格，选中两条，然后在对话框发送：

> 将选中用例的前置条件改为“已登录”，其他字段不变，然后导出这些用例的 Excel。

预期：先出现内联差异卡片，原数据尚未修改，导出步骤等待。确认前发送：

> 先解释一下这次修改会影响哪些用例，不要应用修改。

预期：回答问题，原修改计划继续等待，仍没有新导出文件。然后在差异卡片接受，或对当前提示回复“同意”。

预期：只保存选中的两条；导出随后自动完成。打开 Excel，检查只包含原选择，前置条件为“已登录”，其他字段保留。

## 3. 拒绝与取消后续导出

再次提出“修改标题，然后导出”，在预览卡片点击拒绝。

预期：原数据和版本不变，该计划的剩余步骤已取消，不产生导出。

再提出一次修改并导出，在确认前发送：

> 先不要导出。

预期：取消该计划未执行的导出，当前修改预览仍可独立接受或拒绝。

## 4. 用例列与 Profile

> 给当前用例增加“执行人”列，留给人工填写，然后导出 Excel。

预期：先确认用例变更，再查看并确认 Profile 的列差异，最后自动导出。Excel 包含新列，AI 不编造执行人。可以通过现有 Profile 弹窗确认，不必切回聊天重复下达导出命令。

## 5. 跨能力任务与只读请求

在场景成果可用时发送：

> 先总结当前场景，再估算需要多少条用例，不要生成用例。

预期：计划按顺序解释、估算，展示估算依据；不会启动生成或新增用例。

已有用例时发送：

> 解释 TC-1 的步骤和预期结果，然后把它的标题改为“登录成功验证”，最后导出。

将 TC-1 换成实际编号。预期：先解释，再准备修改预览，等待接受后导出；不能因同一句话含“最后导出”而省略修改确认。

## 6. 恢复与排查

在修改预览等待时刷新页面，或正常停止并重启服务后返回原会话。计划和等待状态应保留；接受后继续原导出，不重复修改。重复提交同一客户端请求不会重复执行。

如果已确认的成果或 Profile 被另一次操作改变，计划应暂停并说明版本冲突，不能导出不相符的版本。若某个计划步骤失败，可回复“重试计划”；后台仅继续尚未完成步骤。进程异常中断且无法确定写入是否完成时，应先查看已有成果，再重新提出剩余要求。

查看聊天内“本次安排”和排查信息，结合 `logs/tcg.log` 的调用编号定位。模型规划和业务内容存在差异，需要在演示所用的真实服务上用以上短流程预跑；本地验证采用受控模型响应、真实接口、SQLite、LangGraph 和实际 Excel。
