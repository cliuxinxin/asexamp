# v3.0.1：围绕对话推进，按需查看成果

界面保留红色强调、首次进入时居中的小输入框和输入框附近的任务、运行模式、Profile、资料用途选项。产生新成果时不自动展开结果表格，也不把阅读位置切换到成果工作区。

## 一次连续演示

1. 新建会话，选择 **Human · 逐步确认**。上传需求，输入「根据这份需求生成测试用例，每个关键阶段让我确认」。
2. 需求理解完成后，留在对话里阅读当前确认提示；输入框旁可看到当前阶段和下一步。点击成果卡片或「查看当前成果」才打开详情。
3. 关闭详情，回到原来的对话位置。输入「先解释一下第二条需求，不要继续」，检查系统只解释，并保持当前确认点。
4. 输入「同意，继续」。场景完成后仍通过对话提示确认，不自动打开场景表。
5. 在输入框先写一段修改草稿；点击查看场景，检查需求关联，选择要修改的行，再点击「在对话中修改所选」。已有草稿应保留，输入框上方显示具体目标。补充修改要求后发送。
6. 修改后查看新版本，满意后在对话中说「同意，继续生成用例」。生成用例和评审结果时重复相同交互；详情中可以查看步骤、预期结果、场景和需求关联。
7. 打开较早消息中的历史成果，检查版本与只读提示。关闭后输入「同意，继续」，仍应确认当前流程的结果。查看历史版本本身不应更改当前确认对象。
8. 阅读较早的聊天记录时等待新消息。页面不应抢走阅读位置；点击「回到最新对话」再查看最新消息。
9. 完成后输入「总结这批用例覆盖了哪些业务」，直接在对话中阅读回答；需要核对具体数据时再打开对应成果。

业务动作都在聊天里提出。成果详情用于核对数据和选择条目；关闭或查看历史成果不会自动确认、生成或修改数据。

## 本轮验证边界

本轮使用前端组件交互测试验证打开、返回、草稿、阶段提示和聊天请求，另做 TypeScript 与生产构建校验。真实浏览器页面因环境访问策略受阻，未完成视觉验收；未连接用户的实际内网模型。演示前应完成模型连接测试，再按上述步骤预跑。
