# 文档按需读取与 Agent 执行

新版智能模式继续使用 Python、LangGraph 和本地 SQLite，不增加向量数据库、Embedding API 或前端选择项。原有 `.env`、Header 鉴权、minimal 内网网关模式和 60 分钟超时配置继续生效。

## 执行方式

1. **规划**：先读取文档目录、范围、已有成果摘要和确认记录。文档原文不会自动放进每次规划请求。
2. **按需查阅**：Agent 可以选择 `search_documents` 和 `read_document`。搜索使用本地英文词与中文二元词匹配，读取只允许本次任务范围中的段落 ID。搜索无匹配时返回空结果，不用第一页冒充相关内容。
3. **完整分析**：要求从全文设计时，逐批检查全部业务来源，每批原文的序列化预算为 12,000 字符。已通过校验的批次持久化，任务重试和重启后可以复用。全文分析不会退化成只读搜索前几条。
4. **整合与生成**：跨批业务图关联使用已提取的结论；场景按需求组生成，用例按场景组生成，每组只取相关证据。导入已有用例时也逐批读取全部输入，再处理模型输出分页，避免只导入前一部分。原有依据与稳定引用保留。
5. **确认与交付**：保留业务图确认和“按当前信息继续”。已完成且覆盖检查通过的结果直接进入总结。总结使用已验收的成果和覆盖统计，不重新读全文。

文档读取、复用、批次完成、补充检查和局部修正会通过 SSE 出现在现有“分析与依据”区域。需要核查请求时，展开调用详情里的“查看发送内容”。`minimal` 模式仍是上游完整 JSON 返回，前端 SSE 负责进度及结果传递。

## 格式错误与遗漏分开处理

格式校验失败时，系统把错误字段、期望类型和必要约束发给模型，只接收该字段的替换值，应用到服务端保存的原草稿。不会让模型为了改一个 description 而重新生成整个需求列表。非法修改其他字段、丢条目和改有效稳定 ID 会被拒绝。

例如 `items[3].description` 需要字符串时，修正请求只携带该字段及必要约束。修正模型必须返回同一路径和替换值；原有第 1、2、3 条及其他字段由服务端保留。无效的业务图节点 ID 可以纠正，其边引用由服务端同步更新；已合法且唯一的节点 ID 保持不变。

如果发现某段资料尚未被分析，则另发一次只包含遗漏段落的补充请求，允许增加有依据的新需求。目录、背景说明等可在 `report.evidence_review` 中说明为什么不属于测试需求；这不是把原文引用自动算成测试覆盖。未确定的信息必须保留，不允许编造默认业务规则。

失败信息会给出字段路径与期望格式，诊断记录保留最初校验问题。草稿与成功调用保存在本地，重试只继续未成功的步骤；认证头值、模型正文和修正字段值不会进入普通诊断日志。请求核查记录和 SSE 正文属于当前任务的业务数据，可以按原有方式查看。

## 本地升级和核查

合并后的代码在项目目录执行 `git pull --ff-only` 更新，停止旧进程后重新运行 `python3 start.py`。保留原来的 `.env` 和 `data` 目录，不需要重新填写模型信息。

先用一份脱敏需求走完“分析 → 确认方向 → 生成”，再试大文档和失败任务的“重试”。核查时关注当前批次、引用段落、遗漏或待确认说明，以及“查看发送内容”中的实际请求。流程展示的是执行动作、依据和阶段结论；业务结论仍需要结合原文复核。

应用的格式校验错误与网关返回的 HTTP 错误分别记录。若提供商调用已成功，而随后出现 `OutputValidationError`，应优先检查 `validation_error.path` 和 `expected`；不能仅凭应用返回的 400 判断为 Header 鉴权失败。

## 范围与限制

- 搜索是本地关键词检索，不是语义向量检索；无匹配时可换关键词或指定段落。
- 文档工具每个补充指令周期最多执行 4 次。单次读取最多 12,000 个序列化字符，输出明确标出片段和遗漏；字符数不是模型 token 数。
- 规划和总结按需缩短记忆、业务图及成果预览，保留总数和省略标识；数据库中的完整需求、用例及确认记录不随预览缩短。单次请求仍有整体字符预算，超限时明确提示缩小范围，不把截断的业务成果当作完成结果。
- 原文只在分析批次或相关读取请求中发送。模型生成已提取事实仍消耗 token，不能宣称总消耗固定下降某个比例。
- 已校验分析批次在当前任务内跨重试/重启复用，相关指令、深度或确认上下文变化会改变缓存指纹。这不是跨所有对话复用的永久语义缓存。
- 跨批次关联使用有限大小的结论窗口；超出窗口的跨模块依赖会明确提示仍需复核。单个结构化场景本身过大时会停下并提示拆分，已有分析保留。
- 结构化需求/分支关联统计是设计覆盖，并没有执行测试，也不能自动证明业务理解完整。

受控测试使用累计 60,882 字符的合成来源（按段落文本计）：旧共享上下文构造为 67,172 字符，新版首次规划为 8,293 字符，约减少 88%，规划没有携带原文段落；全文拆为 6 批，最大完整分析上下文为 14,194 字符（包括任务约束、历史摘要等）。这组数字来自本地受控模型，用于验证上下文构造，不代表真实模型速度、质量或计费。
