# v2.9.3：在一个聊天框里走完整个流程

沿用原来的红色强调、居中开始页和两行输入框。MODE、文件用途、Profile 和任务选项仍在输入框附近。任务选项只是快捷方式，中途估算、解释、修改和继续直接用自然语言表达。

成果区域用于查看表格、展开步骤和上下游关系。业务操作通过聊天完成；当前结果后只显示一个待答提示。每次看到新提示再回复“同意”，这次回复只处理这个提示。需要改动就直接提出，满意后再同意。

## 准备

使用新项目和新对话，在输入框附近选择 Human · 逐步确认。上传 `examples/conversation-v290/login-requirements.md`，用途选择需求正文。模型连接设置沿用原配置；上下文容量由服务器判断，无需填写客户端容量。

新项目便于展示澄清：同项目已经确认过的规则可能被直接复用，实际模型也可能提出不同的问题和假设。

## 主流程与中途修改（按顺序演示）

| 步骤 | 在聊天框输入 | 应看到 |
| --- | --- | --- |
| 1 | 根据上传资料生成测试场景和用例，每一步都等我确认。 | 理解资料；如需澄清，显示问题和建议假设。 |
| 2 | 同意 | 采用当前问题的建议答案，更新理解；接下来等待确认需求理解。如果建议不正确，直接写出正确答案。 |
| 3 | 同意 | 确认理解，生成场景；等待确认场景。 |
| 4 | 这些场景大概需要多少条 case？只估算，不生成，也不要继续。 | 回答数量区间、理由和假设；确认点和成果版本不变。 |
| 5 | 解释一下登录场景对应的需求，先不用继续。 | 解释并显示依据；仍等待确认场景。 |
| 6 | 上传 `examples/conversation-v293/session-revocation.md`，然后说：这份是补充需求，先更新需求理解，给我确认后再往下。 | 先保存新的理解，回到理解确认；已有场景暂不改动。上传本身不会更新成果。 |
| 7 | 同意 | 只按新理解更新受影响的场景，然后等待确认场景；此时还不生成用例。 |
| 8 | 同意 | 使用当前场景生成用例草稿，然后等待确认草稿。表格可看前置条件、每个 step / expected result、场景和需求。 |
| 9 | 只把登录成功用例的标题改得更清楚，步骤和预期保持不变，先给我看预览。 | 出现修改预览；对象有多个时系统会问具体是哪一个，直接回复表格中的实际编号。 |
| 10 | 同意 | 只应用这次修改预览；仍等待确认用例草稿，不会顺带开始评审。 |
| 11 | 同意 | 确认当前草稿，开始 AI 评审，完成后等待确认评审结果。 |
| 12 | 总结这次评审的问题，解释登录用例的验证目的，不要修改，也不要结束任务。 | 给出解释与总结，保留当前确认点。 |
| 13 | 同意 | 确认评审结果，完成这次主任务。 |

实际模型的数量和编号可能不同。无需为了使用聊天去勾选表格，直接描述或输入真实编号即可；勾选仍可作为可选的范围辅助。

## 已有用例时回改上游

在步骤 8 的草稿确认处，可加一段循环：

1. 输入“把需求理解中登录相关描述写得更清楚，不改变规则，只改理解，先给我确认”。有新业务规则时先提供具体内容或上传资料，不能只要求模型猜测。
2. 新的理解保存后回复“同意”：只更新受影响场景，再次等待确认。
3. 回复“同意”：只更新关联用例，保留稳定编号、无关用例及人工数据，再次等待确认草稿。
4. 回复“同意”：评审当前草稿；评审结果再由下一次“同意”确认完成。

如果在评审结果确认处回改上游，同样先逐阶段确认理解、场景、草稿；更新后的用例会重新接受设计质量评审，再等待最终确认。原来的任务与 LangGraph 检查点保留。

## 其他要点也用这个聊天框

- 项目澄清：输入“列出本项目已确认的锁定规则和来源”。在同一项目新建对话再问一次，应能复用已确认结论。输入“这只是本次任务的假设”时不会共享为已确认事实。
- 覆盖：查看场景行的关联需求、用例行的主场景和需求，或问“哪些需求还没有场景，哪些场景还没有用例？”结构关联不能等同于测试已经执行或业务覆盖充分。
- 固定格式样例：完成后输入“把编号 XXX 和 YYY 的用例保存为当前项目 Profile 格式样例”。替换为实际编号；样例只指导格式与写法，不成为其他需求的业务事实。
- 学习模板：上传 `examples/conversation-v260/scenario-template.xlsx` 和 `case-template.xlsx`，用途为模板/格式样例。输入“学习这两份场景和用例模板，先展示建议”。看到模板确认提示后回复“同意”，应用到当前 Profile，两类列定义相互独立。
- 导出：输入“按当前 Profile 分别导出全部场景和用例为 Excel”，在回复中下载文件。如果新增必填列缺少内容，按聊天提示补充或要求只补缺项。
- 完成后总结：输入“面向业务人员总结现有用例覆盖什么、还有什么限制，不要修改”。
- 暂停与恢复：输入“先暂停，等我确认”。系统在当前步骤保存后的安全边界停下；看到暂停提示后可提问、修改或回复“继续”。
- 仅生成场景：从新任务开始说“只生成场景，不要生成用例”。达到这个目标后，普通“同意”不会扩大范围；要继续需明确说“继续生成用例”。

## 自动模式与验证边界

新建对话选择 Auto，输入“根据上传资料自动完成理解、场景、用例和评审”。主生成流程不设置 Human 的四个确认停点；明确暂停、业务澄清和错误仍会显示当前待处理事项。

本次程序验证使用真实 HTTP、SQLite、LangGraph 和可控模型响应，覆盖单次确认、重复或过期确认、中途提问、上游修改后逐阶段回归、模板应用、原始开始页和表格交互。尚未连接你的真实模型服务；自由文本的实际识别效果需要使用上述对话预跑。当前环境未完成真实浏览器视觉验收。
