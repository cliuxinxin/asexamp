# v3.0.6：模板更改确认、过程成果查看和 Excel 导出

保留原来的对话首页和输入框选项。主流程仍由对话推进，成果和模板明细按需点开。

## 一次走通本版交互

1. **学习模板**：上传场景或用例 Excel 模板，选择“学习模板”，发送学习要求。助手回复总结将修改哪些 Profile 设置；此时尚未应用。
2. **查看更改**：点击输入框上方建议区的 **查看 Profile 更改**。弹窗展示更改前后，包括表头、字段、列顺序、字段定义、填写方式、必填及默认值。
3. **手动确认**：勾选要应用的配置项，点击 **确认应用所选更改**。未勾选项保留原配置。每套导出列作为一组确认，保证列顺序与规则一致；不是分别勾选某个单元格。仅查看或关闭不会保存。确认后建议消失，对话记录本次应用摘要。
4. **生成测试**：上传真实需求，选择“生成用例”或“自动识别”，发送 **根据上传需求生成测试用例，每一步让我确认。** 按提示回答澄清，并依次确认理解、场景、用例草稿和评审结果。
5. **查看过程成果**：点击输入框上方 **查看当前成果**，在窗口顶部的 **过程成果** 中切换需求理解、场景、用例草稿和评审结果。需求理解中可看业务图，场景和用例中可看关联及步骤。未生成的阶段不会出现。过程查看不会确认、重跑或改变当前任务。
6. **核对历史版本**：同一用例成果可以查看生成时的草稿和评审后的版本。历史版本标为只读；可切回当前版本继续查看。点击 **返回对话** 后，输入草稿与当前确认点保留。
7. **前端导出 Excel**：在场景或用例成果窗口右上角点击 **导出 Excel**。选择全部/所选条目、格式 Profile；用例还可选择一条用例一行或一个步骤一行，然后点击 **下载 XLSX**。该按钮直接下载，不需要模型调用。历史版本按正在查看的版本导出，默认采用该版本保存的模板配置。从对话打开部分用例时，只导出当前显示的条目；可通过过程成果列表切换到完整版本。

## 两项需要核对的行为

- 打开 Profile 差异后，若其他人已修改 Profile 或当前模板建议被替换，旧确认会被拒绝，不会覆盖新配置。关闭后重新学习、查看新建议再确认。只应用部分设置后，该建议整体结束，未勾选项不会在下一次“同意”时被意外应用。
- 模板必填字段缺少内容时，导出窗口会列出缺项。在聊天中要求补全，再查看、导出更新后的版本。人工执行字段允许留空。导出窗口不会修改历史成果，也不会偷偷触发 AI 补全。

## 升级

停止旧服务，备份原数据目录，解压新版到新目录，然后指向原数据目录启动：

```bash
python start.py --data-dir /path/to/existing/data
```

项目、资料、Profile、成果及版本保留。旧的待确认模板只要 Profile 版本尚未改变，也可以打开新的差异预览。

## 接口增量

- `GET /api/chats/{chat_id}/profile-change?prompt_id=...`：读取服务端实际合并后的配置差异。
- `POST /api/chats/{chat_id}/profile-change/apply`：提交 `prompt_id`、`expected_version`、`selected_keys`；服务端应用已保存的建议值，不接受客户端替换整个配置。
- `GET /api/chats/{chat_id}/artifacts`：返回当前对话的可见成果与阶段版本目录，不包含全文；选中后才读取相应成果内容。
- `GET /api/artifacts/{id}/export-options` 和 `/export`：新增可选 `revision`，支持读取所选历史版本的导出配置和 Excel 内容。

本版用可控模型响应验证真实 HTTP、SQLite、Tool Calling、LangGraph 与实际 Excel 内容；尚未连接你的模型服务验证模板学习质量。浏览器视觉验收尚未完成。
