# 日常交互改进 · v3.0.15

本版保留 v3.0.14 的统一工作区和提示词 JSON 嵌套修复，补齐以下三个现有流程。

## Auto 自动采纳澄清

选择 Auto 后，遇到澄清问题会采用当前建议答案，通过原有澄清处理节点更新理解并继续。没有具体建议时，按已有明确需求处理，未说明的条件仍标记待确认。Human 模式继续等待逐题答复与阶段确认；用户主动暂停时，Auto 也会停在现有确认节点。

自动采纳的答案按本次方案保存到项目澄清，其来源会标记“Auto 模式自动采纳”，不会冒充用户逐题输入。失败后重试复用已保存的澄清来源。

## 填入输入框后再编辑

澄清建议、互斥答案与文本快捷回复旁增加“填入输入框编辑”。点击会将完整内容填入并聚焦输入框，有草稿时追加到草稿末尾；不会发送消息。澄清内容包含题号和问题文字，编辑后可准确对应原问题。原有直接采用或发送按钮仍可使用。

## 补充知识用于当前成果

例如：选中当前用例，输入“补充规则：登录前必须完成短信验证，请更新所选用例”。系统先保存规则，再由成果更新步骤使用刚保存的来源 ID 生成修改建议。打开工作区查看并保存后，正式成果才产生新版本；未选择的条目保持原样。

仅上传资料、目标不清楚或相关性不明确时，系统应先核对或询问。明确“只保存，不修改”的要求只保存资料；待确认假设和格式样例不会当作已确认业务规则。提示词强化了后续操作要求，后端负责传递确切来源并保持原有权限和范围限制。

## 升级与验证

这是包含前后端修改的完整版本，需要停止旧服务后使用新版启动。保留原数据目录，运行 `python3 start.py --data-dir /原数据目录`。本次保留所有依赖版本，不需要日常启动时重新构建前端。

定向验证包含真实 SQLite、LangGraph、HTTP 路径，以及 JSDOM 前端交互；模型返回使用可控响应。未调用用户真实模型，无法保证任何模型都能稳定选择正确计划。执行结果与范围记录在 `RELEASE-MANIFEST.json`。
