# v3.0.5：三图、单一阶段提示与人工评审

## 本次变化

- 需求理解明确生成业务流程图、领域思维导图、状态转换图，打开需求理解成果即可查看。澄清和修改理解后同步刷新图。
- 阶段状态只保留输入框上方的一处。回复区域不再重复显示“正在处理当前步骤”或纯阶段确认卡；澄清问题、评审意见和错误内容仍在对话里展示。
- 普通“生成测试用例”默认包含 AI 评审，自动识别任务时也如此。只有明确要求“只要草稿，不评审”等提前停止目标，才跳过后续评审。
- Human 模式依次确认需求理解、场景、用例草稿、评审结果。评审结束后，对话中自动展开评审摘要和意见表，显示说明、相关用例、依据与本次评审范围；不会自动打开成果弹窗或自动完成。评审的待确认问题、范围排除理由也会显示。

## 一次测试这些交互

1. 新建会话，上传需求，选择“自动识别”和“逐步确认 / Human”，发送：**根据上传的需求生成测试用例。** 不需要额外写“带评审”。
2. 等待需求理解。若出现澄清，采用建议或输入真实答案；回答只更新理解，随后仍需单独确认。点击查看需求理解，应能看到三个图；页面当前阶段只在输入框上方显示一次。
3. 回复 **确认需求理解并继续**。查看场景与对应需求，再回复 **确认场景并继续**。
4. 查看用例步骤和预期，回复 **确认用例草稿并继续评审**。
5. 等待 AI 评审意见在对话中出现。应显示摘要、逐项意见、相关用例与依据；没有逐项意见时会明确写“本次 AI 评审未列出问题”。任务仍等待确认。
6. 先输入 **解释一下 TC-实际编号 的步骤和预期，暂时不要继续。** 应得到解释，评审确认点保持不变。
7. 输入具体补充意见，例如 **把 TC-实际编号 的第一个预期改为「你的正确预期」，保留其他内容，先修改，不要完成。** 修改后回到用例草稿确认；回复确认后，AI 基于修改后的用例再次评审，随后再次等待评审结果确认。不会重新理解需求或生成场景。
8. 点击输入框上方的 **确认评审结果并完成**，或输入等价确认，任务才完成。快捷回复不会清除尚未发送的输入草稿。
9. 另开会话切到 Auto，只发送 **根据上传需求生成测试用例。** 正常情况下自动完成理解、场景、用例与评审；必要澄清仍会等待答复。

## 图与旧数据

模型在原有需求理解/修改调用中返回三个图，不因这项改动固定多调用一次模型。有效的当前图会保留。模型漏图时，界面会补上明确标注“待补全”的对应视图，不把条目顺序编造成业务流程或状态转换；大文档分批结果也不能冒充完整业务关系图。

已经保存的一图历史成果不会在打开时被悄悄改写。可以在聊天中说 **根据当前需求补全业务流程图、领域思维导图和状态转换图，保留需求条目，不继续生成。** 查看更新版本后再确认。

本版使用可控模型响应验证真实 HTTP、SQLite、Tool Calling 和 LangGraph 交互；尚未连接你的模型服务验证实际图与评审质量。原 Azure / 兼容网关配置及服务端上下文容量处理保持兼容。

## 接口增量

`GET /api/chats/{id}` 的 `conversation_prompt` 在 `kind="case_result_review"` 时新增可选 `review`：

```json
{
  "summary": "本次评审摘要",
  "issues": [{"title": "评审意见", "detail": "说明", "case_ids": ["TC-1"], "refs": ["实际证据编号"]}],
  "scope": {"reviewed_count": 1, "total_count": 1},
  "notes": ["其他说明"]
}
```

内容取自该确认点绑定的成果版本中的最新 `review_reports`，历史阶段消息也使用对应版本的评审摘要，避免显示生成草稿时的摘要。`POST /api/chats/{id}/turns` 路径和确认/提问/补充意见方式沿用 v3.0.4。原始 `busy` 状态仍供页面控制使用，只去掉重复渲染。
