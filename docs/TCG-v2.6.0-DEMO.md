# TCG v2.6.0 连续对话演示与验收

这一版把普通聊天接到统一的业务能力目录。核心生成顺序仍由固定工作流执行；解释、估算、修改、共享、联动和导出在同一会话里调用。无需先选择“估算”或“修改”任务。

## 准备一次，连续演示

1. 解压新版，按 README 启动并配置你的模型。升级时继续使用原数据目录，先保留一份备份。
2. 创建“员工门户演示”项目和会话 A。选一个 Profile；需要展示关键确认时选 HITP。
3. 包内 `examples/conversation-v260/` 提供两份 Excel 模板、一份需求和一份变更说明。上传附件可以用按钮；下表的业务操作全部直接在聊天框输入。
4. 另建同项目会话 B，用于演示共享。共享指同一服务/数据目录中的项目内容；此版本没有增加成员登录或权限系统。
5. 先确认空会话输入区紧凑；进入对话后展示区域较宽，可拖动结果面板宽度。选择“学习模板”等快捷任务会填入提示词，但已经编辑的草稿应保留。

## 按这个顺序串测

如果生成结果不足三条，把下面的“第二、第三条”换成实际存在的序号。序号对应当前显示顺序；多个成果可能对应时，回答系统列出的那一份。

| 步骤 | 操作或直接输入 | 实际检查点 |
|---|---|---|
| 1 | 上传包内两份 Excel 模板：“分别学习这两份场景和用例模板，并应用到当前 Profile。” | 返回实际 Profile 版本；场景列和用例列分别保存，人工备注保持人工填写策略。 |
| 2 | 上传需求文件：“根据这份需求做测试设计，需要我确认的地方再问，整个任务先做到场景。” | 开始主流程；保存“停止在场景”的任务条件。 |
| 3 | 出现澄清后：“采用全部建议，锁定时长改为 10 分钟，保存到项目，但先别继续。” | 建议采用后收起；答案变为 10 分钟；项目保存成功；任务仍等待。没有依据的建议应标为假设。 |
| 4 | 在卡片把其中一个答案改一下，刷新页面；确认聊天与卡片读到同一草稿。然后保存。 | 新内容保留；旧页面保存时发生版本冲突会提示刷新，不静默覆盖。 |
| 5 | 切到同项目 B：“项目已经确认的锁定时长是多少？依据是什么？” | 引用已确认的项目澄清回答，无需 B 重填。未共享的会话草稿不能成为项目事实。 |
| 6 | 回到 A：“按这些答案继续。”理解确认后：“理解正确，继续生成场景。” | 只推进当前节点，使用保存的答案；到场景后停下。 |
| 7 | “只估算第二、第三个场景大概需要多少用例，先不生成。”再问：“那只算异常的呢？” | 展示逐场景数量、合计和假设；追问继承相同子集；没有新用例或修改版本。 |
| 8 | 紧接着说：“可以。” | 只认可刚才的估算；不能误确认背后的场景节点，也不能采用早先的旧预览。 |
| 9 | 上传包内变更说明：“结合这份管理员强制下线说明，更新受影响的需求理解和场景，仍然先别生成用例。” | 纳入新来源，按影响修改；无关条目和已有用例保留；停止条件不丢失。影响涉及全局时，系统说明需要扩大分析范围。 |
| 10 | “把需求理解中失败计数的说明写清楚，并同步到相关场景，先给我看差异。”随后：“应用这些修改。” | 预览不写入；实际显示前后差异；应用后保存分析和关联场景的新版本，保留稳定编号。 |
| 11 | “现在按最新场景生成用例并评审，展开每一步操作和预期结果。” | 使用最新场景继续主流程；显示真正的 action/expected 内容和评审结果。 |
| 12 | “解释第三条用例，再把它的步骤写清楚，保留人工备注，先不保存。”随后：“应用这项修改。” | 先解释再预览；应用只修改该条；已有人工字段不变。可先在该条填入一条人工备注以便核对。 |
| 13 | “把刚才用例对应的场景写清楚，并同步更新这个场景的关联用例；其他场景别动，先看差异。”随后：“应用。” | 沿真实关系定位场景和正确用例分支；关联用例依据新场景草案修改；其他场景的用例不变。 |
| 14 | “展示需求、场景和用例的覆盖，哪些缺用例、哪些还没同步？” | 渲染真实关联与版本统计，能看到缺失和过期关系；结构上有关联不代表业务已充分覆盖。 |
| 15 | “只评审这些用例，先别修改。”然后：“用产品经理能理解的方式总结这些用例，列出锁定相关编号。” | 评审和总结有实际依据；用例版本不变；编号来自真实用例。 |
| 16 | “把当前第一条用例的写法保存为本项目 Profile 的样例。”在 B 中使用同一 Profile 生成少量新需求的用例。 | A 返回实际 Profile 版本；B 的生成上下文使用该格式样例，旧业务引用不被当成新需求。 |
| 17 | “按刚才学习的模板，把最新场景和最终用例分别导出 Excel。” | 聊天出现两个下载文件；分别检查工作表、列顺序和自定义字段。下载绑定生成文件时的版本，之后修改成果不会改变已生成文件。 |
| 18 | “第三条再简洁一些，先预览。”随后：“取消这次修改，主任务保留。” | 只撤销这项预览；原成果和主任务保持。再次应用已撤销预览应被拒绝。 |

## 插入几个能体现对话流转的操作

- **边运行边提问**：生成下一阶段时问“总结目前已经保存的场景”。应基于已保存版本回答；生成继续，不因任务推进而拒绝回答。
- **直接修改**：停在场景确认时说“把第三条的条件写清楚，其他不动”。范围明确时直接保存新版本，仍停在确认节点；无需再输入一次“应用”。
- **后来的暂停优先**：发“把第三条写清楚，改完继续”，在修改返回前再发“先别继续”。已经保存的修改保留，尚未执行的继续应取消。
- **取消正在处理的修改**：修改尚未完成时说“取消这次修改”。晚到响应不能重新写入。只有“停止整个任务”才取消主流程。
- **中途补充**：运行中上传资料并要求更新。系统应先记录请求，在安全步骤边界处理；不会声称新资料已经进入此前发出的模型请求。
- **指定成果与追问**：存在多份场景时问“估算一下”；若系统询问哪份，回答“第二份”。应接着完成原估算，不丢失任务。
- **版本冲突**：保留一个预览，再在另一个窗口修改同一成果；回到旧预览说“应用”。不能覆盖新版本，应提示过期。
- **重试去重**：对同一个请求发生网络重试时，应返回同一回执，不重复保存版本或推进节点。

## 如何判定演示通过

不要仅凭助手说“已完成”判断。每一步核对实际成果 ID/版本、修改行、步骤和预期、项目共享来源、停止位置或导出单元格。无数据依据的字段应说明待补充，不能为了填满表格而编造。

本次自动验证使用可控的语义/模型响应，检查实际 SQLite、业务服务、版本和 Excel 内容，也包含前端 DOM 交互及构建。测试生成的固定条数不是你实际模型必须生成的条数。

当前执行环境缺少 FastAPI、LangGraph 和 pytest，依赖安装也未能完成，因此实际 HTTP 启动及完整 LangGraph 生成回归尚未执行；对应测试文件已随包保留。你的内网模型对各种自然表达的识别，需要按本表实际联调。成功的服务层测试不等于所有自然语言问法都已经通过。

如某一步不符合预期，保留那条原话、当时节点和成果版本，并下载对应任务诊断包。对话操作状态还可以在返回的 Turn 回执中检查，避免把意图识别、引用校验和并发冲突混为一类。
