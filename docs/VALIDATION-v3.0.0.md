## 已验证的业务闭环

- Human 四个确认点、Auto 完成、显式暂停、重启后恢复；确认不会重做上一步生成。
- 澄清建议正常显示、采用后收起、未答问题再次等待；项目澄清进入同项目新对话的实际证据与产物引用。
- 估算与解释不生成或修改成果，不推进确认。
- 修改预览与采用、重复/并发确认、过期确认、直接编辑及历史恢复。
- 完成后上传补充资料，只更新理解；确认后依次联动场景、用例与评审。
- 已有理解续做场景、已有场景续做用例、已有用例仅评审，不重跑理解。
- 只评审选中用例；局部修改保留无关条目、稳定编号和人工字段。
- 模板独立学习、缺列补全、样例保存、实际 Excel 单元格。
- 服务器容量拒绝后的有限批次拆分；工具参数错误、重复工具调用、成功写入后的模型失败不重放。
- 阶段成果记录携带现有 React 所需的消息元数据；自动完成后的最终结果、草稿和评审版本可回看。
- 原生模型请求和返回可被失败步骤日志读取；旧已知确认点迁移不会调用模型，位置不可靠时保留数据并提示重新开始。
- 原生调用使用原界面识别的进度事件；请求归档失败时不虚报可查看，取消与错误能区分；阶段等待和完成不因重复查询检查点而重复追加。

## 历史测试处理

旧后端测试属于已删除的控制器/图契约，移入 `legacy-tests/`。前端旧全量测试中有 94 通过、75 失败，失败主要在被替代的独立按钮、澄清输入框、旧路由和 SSE 契约；相关原文件完整归档到 `legacy-tests/frontend/`，其中仍然适用的组件、Profile 和聊天检查保留在当前测试中。77 项通过不表示那些旧架构断言也通过了。

联合验收曾发现启动结果的 `start_context=null` 被当成字典读取，导致后台已启动但聊天报错。已修复空值兼容并重新运行全部当前后端测试，69 项通过。

后续进度复核发现，原生后端与原前端的部分事件名称不一致。完成局部兼容修复后，后端当前全套 76 项通过（14.63 秒），前端当前全套 77 项通过（10.69 秒）。人工确认专项审查没有发现新增缺口。本次没有改变前端业务源码，也没有把本地可控模型验证当作内网模型验收。

最终审查额外验证了诊断写入故障不会改变模型结果或人工等待位置；确认节点恢复不会重复产生业务阶段开始事件。两项复核均已关闭。
