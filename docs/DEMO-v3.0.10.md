# v3.0.10：在同一对话中演示修改、评审和导出

先执行模型连接测试，新建会话，选择“逐步确认 / Human”。上传包内 `examples/conversation-v290/login-requirements.md` 或自己的需求文档。下面编号需换成实际场景/用例编号；无需切换任务类型，业务指令直接在聊天框发送。

| 步骤 | 操作或聊天输入 | 验收点 |
| --- | --- | --- |
| 1 | 根据上传的需求生成测试用例，逐步确认。 | 生成需求理解。若有澄清，核对建议答案后采用或直接回答；回答与确认理解是两个动作。 |
| 2 | 确认需求理解，继续。 | 生成场景并停下；打开场景成果能以表格查看描述、优先级、关联需求。 |
| 3 | 把场景 SC-实际编号 的标题改为“验证有效凭证登录”，需求关联标记为 N/A，只修改场景。 | 输入框上方出现“查看修改预览”。打开看到修改前后和 N/A；此时正式场景、上游需求都未改变。 |
| 4 | 在预览中确认，或对话回复“同意保存本次修改”。 | 只更新场景版本，上游需求不改；仍停留在场景确认。取消预览则两者均不改。 |
| 5 | 打开场景表格，点击手动编辑，修改描述或优先级并保存。 | 表格内容更新，可增删场景行。新增无父关联的行显示 N/A。也可勾选行后向 AI 说明修改要求。 |
| 6 | 根据这些场景估算用例数量，不生成，也不要继续。 | 返回估算，场景版本和等待位置不变。 |
| 7 | 确认场景，继续生成用例。 | 自动完成用例生成并产生 AI 评审建议，中间不要求确认用例草稿。 |
| 8 | 在评审阶段点击输入框上方“查看修改预览”。 | 可查看相关用例、修改前后、步骤及预期结果；正式用例尚未应用建议。 |
| 9 | 评审时请重点核对每一步操作是否有明确预期，先更新评审建议，不要应用。 | 新评审建议替换待确认建议，正式用例仍不变。 |
| 10 | 确认采用本次评审建议。 | 此时才保存评审后的用例新版本，完成本轮。 |
| 11 | 给当前用例新增“执行人”列，人工填写，删除自定义列“备注”，然后导出 Excel。 | 先展示用例列修改预览。没有“备注”时只说新增即可；已有值保留，人工列不编造执行人。 |
| 12 | 查看修改预览并确认。 | 用例数据先保存；输入框上方接着提示“查看 Profile 更改”。此时 Profile 仍未修改。 |
| 13 | 查看 Profile 差异，确认列设置。 | 自动导出刚修改的用例，聊天里出现下载链接；不用再重复发送“导出”。Excel 有确认后的表头和数据。 |
| 14 | 打开用例表格手动编辑步骤、预期或自定义字段，保存。 | 只保存此次编辑；也可增删自定义列。列改动会产生单独的 Profile 确认建议。已有用例更新后的 AI 评审只产生待确认建议，不自动覆盖手动内容。 |
| 15 | 解释 TC-实际编号 的测试目的，然后总结这些用例。 | 对话返回解释和总结，不修改场景、用例或 Profile。 |

用例也可以独立修改：发送“把 TC-实际编号 的场景关联标记为 N/A，只修改这条用例”，查看预览后确认。已有有效关联默认保留；只有新增无父项或明确要求解除关联时才显示 N/A。需要带动下游重生成时再明确提出，不会为了补齐树状关系创建虚拟需求。

手动表格支持场景行和用例行编辑；自定义列新增、删除入口用于用例。删除稳定编号、步骤等核心结构不被允许，可以通过导出列设置隐藏。编辑局部查看结果时会加载同版本完整表格，避免保存时误删未显示的行。历史版本只读。

一个“同意”只确认当前正在展示的对象。用例数据预览与 Profile 预览分别确认，是为了先检查具体数据，再检查项目级导出规则。若确认前用例或 Profile 已变化，系统要求查看新版本，不会导出旧内容。若原请求没有要求导出，确认 Profile 后仍可使用成果中的“导出 Excel”。

Auto 可在另一会话验证：发送“根据需求自动完成用例和评审”。无需逐项确认时，使用同一评审建议流程自动应用；明确请求暂停、只生成草稿或必要澄清仍按请求处理。

本版验证使用可控模型响应，覆盖真实 HTTP、SQLite、LangGraph、前端交互以及 Excel 单元格。尚未验证你的模型服务对上述自由表述的实际识别效果，演示前请用实际资料和模型预跑一次。
