# v2.9.1：恢复熟悉的开始页与生成入口

这是 v2.9.0 的局部修复。开始页重新使用“你想测试什么？”的欢迎语，输入框居中、默认两行；文件用途、MODE、Profile 和本次方案放回输入框附近，任务按钮位于输入框下方。上传的文件持续显示，可以点击查看用途。

## 从上传资料开始

1. 新建会话，在输入框旁选择 Auto 或 Human。Human 会依次停在需求理解、场景、用例草稿和评审后结果，供你确认。
2. 选择文件用途，再点击回形针上传文件。如果上传的已有用例是本次业务依据，选择“主要需求”；如果仅参考其格式，选择“参考样例”。也可以保持“自动识别”，在系统询问用途时确认。
3. 点击输入框下方的“生成用例”，查看或修改自动填入的文字，再发送。例如：“根据我上传的用例生成测试用例，保留其中明确的业务规则。”
4. Human 模式看到需求理解后，可以先问“解释一下这个理解”，或提出修改。确认需求理解后才生成场景，再逐步确认后续成果。

也可以保持“自动识别”，直接在聊天框说明需求。明确选择的首次生成任务可直接进入主流程；默认自由聊天，以及已有任务中的提问、修改、估算和继续仍由对话调度处理。

## 用几句话检查操作是否顺畅

| 时机 | 操作 | 预期 |
| --- | --- | --- |
| 新建会话 | 查看页面 | 输入框在中间，选项就在旁边；没有空成果区占位 |
| 文件上传后 | 点击“生成用例”并发送 | 能进入处理；Human 停在第一个需要确认的节点 |
| 等待场景确认 | 输入“只估算这些场景大概需要多少用例，先不生成” | 返回估算，仍保留当前确认节点 |
| 等待确认 | 输入“解释一下当前结果” | 返回解释，不代表确认或重新启动 |
| 修改完成 | 点击当前阶段的确认按钮 | 使用修改后的成果进入下一阶段 |

选择“参考样例”的文件不会自动变成业务依据。如果系统要求确认资料用途，可明确回复“这份文件是本次业务依据，请作为需求使用并继续”。

## 修复与验证范围

- 首次明确选择“分析需求 / 生成场景 / 生成用例”时，直接调用对应主流程入口，保留 MODE 和 Profile。
- 后端兼容模型返回的 `generate_cases`、`generate_scenarios` 等既有任务名称；`goal: cases` 表示停在用例草稿，不自动扩大到评审。
- 会话尚未加载或首条发送尚未完成时，后续聊天不强制变成启动指令。
- 本版 25 项前端交互测试通过，覆盖选项位置、上传与发送、加载和并发边界、人工确认、历史成果及选中范围。
- 本版 16 项后端定向测试通过，使用真实 HTTP、SQLite、LangGraph 和受控模型响应，覆盖上传用例生成、Auto、Human 四阶段确认与当前连续对话旅程。
- 另尝试了 v2.7.1 的旧人工旅程测试，其“保存澄清后仍留在旧输入节点”断言在未修改的 v2.9.0 也失败。当前行为是更新理解后等待理解确认；本版未修改该历史断言。
- 未连接你的真实模型服务，未运行全部历史测试。浏览器访问本地页面受环境限制，未完成实际浏览器视觉验收；前端交互验证使用 DOM 测试。

## 升级

停止旧服务并备份原 `data` 目录。将原数据和模型配置保留给新版，运行 `python3 start.py`（Windows：`py -3.12 start.py`）。压缩包包含前端构建产物，日常运行无需 Node.js。打开页面后刷新一次；服务健康接口 `/api/health` 返回版本 2.9.1。

完整功能的连续演示与资料继续见 [v2.9.0 演示](DEMO-v2.9.0.md)；任务设置的位置以本页为准。
