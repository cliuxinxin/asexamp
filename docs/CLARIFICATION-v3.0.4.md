# v3.0.4：澄清闭环与输入框上方的快捷回复

## 修正内容

已提交且非空的澄清答案由后台匹配当前问题，再确定哪些问题已回答。模型重复返回旧问题、遗漏未答问题，均不能改变这个判断。回答一部分只保留未回答的问题；全部回答后进入下一步。人工模式会停在“确认需求理解”，不会把提交答案当成确认需求理解。

报告允许增加 `clarification_note` 等说明字段，仍检查核心字段类型、步骤、稳定编号和证据引用。不同批次的扩展说明返回字符串、对象或数组时，合并会保留内容；模型不能借报告字段写入内部依赖、完成状态等元数据。

模型在应用答案时新提出的问题会作为“补充问题（待核实，尚未确认为业务规则）”显示在成果说明，并在聊天中提示。它们不是用户已经确认的规则，也不自动把本次已回答的问题重新打开。需要处理时可继续在对话中提出。

## 快捷回复

快捷回复位于输入框上方、输入框边框之外。点击立即发送对应消息，输入框中已有的草稿保留；希望自行修改答案时，直接在输入框说明问题和答案。

| 当前位置 | 快捷回复 | 实际效果 |
| --- | --- | --- |
| 等待澄清 | 采用 Q1 建议 | 只提交该题答案并更新理解，其他未答问题继续保留 |
| 等待澄清 | 采用全部建议并更新理解 | 提交当前所有建议答案，人工模式下随后单独确认理解 |
| 等待澄清 | 先解释澄清问题 | 查询、解释问题依据，不采用答案、不修改或推进流程 |
| 等待需求理解确认 | 确认需求理解并继续 | 确认当前版本，进入场景生成 |
| 等待需求理解确认 | 先解释需求理解 | 解释当前内容，保留当前确认点 |
| 后续人工确认点 | 对应阶段确认 | 只确认当前阶段；新阶段仍需下一次确认 |

澄清尚未答完时不会提供阶段确认快捷回复；后端也拒绝用普通阶段确认代替答案提交。按钮绑定当前提示，处理期间禁止重复点击；失败后保留建议供主动重试。

直接输入的自然对话继续使用完整工具集。快捷回复只是明确本次操作范围：询问开放查询工具，回答开放澄清提交工具，确认开放当前阶段确认工具，仍由原生 Tool Calling 完成操作。

## 升级与复测

1. 停止旧服务，解压新版，沿用原数据目录和 `.env` 启动。例如：`python start.py --data-dir /path/to/existing/data`。Azure 与原网关配置均保留。
2. 打开原会话。若仍等待澄清，采用一个建议或在聊天中回答一题，检查该题消失、其他问题保留。
3. 点击“先解释澄清问题”，检查系统回答后仍停在原确认点，理解版本没有因解释而改变。
4. 采用剩余建议。Human 模式应转到“确认需求理解”，不再重复旧问题；检查更新后的理解包含已提交答案。
5. 点击“先解释需求理解”，检查仍等待确认；再点击“确认需求理解并继续”，进入场景生成，后续按各阶段提示逐一确认。
6. 项目澄清仍默认共享。使用同一后端的同项目会话可以复用；已存内容无需重新上传。

若旧任务停在失败的 `apply_clarification`，通过“重试当前步骤”继续即可；已有答案来源会复用，避免重复保存。不必为这次澄清回环新建会话。若任务早已取消或被其他修改改变状态，则按页面当前状态继续，不能保证恢复任意旧执行位置。

Auto 模式保留原定义：必要澄清时暂停，答案完成后自动继续；只有 Human 模式逐阶段确认。

## 验证范围

使用可控模型响应复现了“保留旧问题”和“报告额外字段”问题；验证部分回答、全部回答、同会话继续、澄清失败重试、项目共享、输入框上方直接快捷回复、草稿保留及查询操作不推进。Azure 连接的自动与四个人工节点流程也通过了回归。

尚未连接用户的真实 Azure/内网模型。本轮使用组件交互测试及生产构建验证前端，没有进行真实浏览器视觉验收。
