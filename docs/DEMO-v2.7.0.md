# TCG Case Agent Local v2.7.0 连续演示指南

本指南用一个项目、一条持续对话演示“先理解、再确认、再生成、生成后继续讨论和修改”的完整路径。演示者复制下方提示词到聊天框即可；按钮名称以当前前端为准。

> 重要边界：本项目的自动化验收使用可控模型输出，已验证 HTTP、LangGraph、SQLite、版本、联动修改和 Excel 文件；它不证明任意真实模型都能把每句自然语言稳定路由到同一个能力。现场演示前必须用实际模型预跑。若模型追问目标成果，请在结果面板中打开对应成果后重发，不要改成内部命令。

## 一、准备材料

使用仓库内已有文件，无需新增 fixture：

- 需求正文：`examples/conversation-v260/login-requirements.md`
- 需求变更：`examples/conversation-v260/forced-logout-change.md`
- 场景模板：`examples/conversation-v260/scenario-template.xlsx`
- 用例模板：`examples/conversation-v260/case-template.xlsx`

开始前：

1. 新建项目和对话。
2. 在“需求来源”上传 `login-requirements.md`，文件用途选“需求正文”。
3. MODE 选“人工确认关键节点”。
4. 记录当前 Profile 名称，后面把它保留为“样例 Profile”。

每次只发送一条提示，等待本次操作结束后再发下一条。结果面板显示的 `vN` 是本演示判断“是否写入”的依据。

## 二、从澄清开始生成真实成果

### 1. 启动主任务

复制：

```text
请基于当前登录需求设计测试场景和测试用例。先识别会影响设计的缺失规则，在关键节点等我确认。
```

预期：任务进入“需要你确认”，显示澄清问题、建议答案、依据和“采用全部建议”。若实际需求与模型判断足够明确而没有澄清问题，这是模型语义差异，不是框架故障；现场若必须展示澄清卡，应使用预跑时确实会触发问题的模型和需求组合。

### 2. 采用、编辑、保存和共享澄清

点击“采用全部建议”。

预期断言：

- 已采用的问题从建议列表消失；建议文本进入“回答澄清问题”草稿。
- 这一步只更新草稿；状态仍显示“答案尚未提交”，主任务没有继续。
- 可以修改草稿，例如把锁定时长改为“连续失败 5 次后锁定 10 分钟”。失焦后刷新页面，编辑内容仍保留。

点击“保存答案”，再点击“共享到项目”。

预期断言：

- 状态依次显示“答案已保存”和“已共享到项目”。
- 保存、共享都不推进原任务。
- “共享到项目”在成功后不可重复点击；项目记忆/后续同项目对话可复用已确认事实。

最后点击“提交并继续”（已单独共享时，复选框状态不影响重复共享）。

预期：原任务继续到“确认理解与方案”。点击“确认理解，生成场景”，随后到“场景确认”。检查需求编号、场景编号和引用，再点击“确认场景，继续生成用例”。等待评审和总结完成。

预期断言：

- 成果由主工作流实际生成，不是手工预置；可打开需求理解、测试场景和最终用例的版本历史。
- 用例详情包含结构化“操作”和“预期结果”。
- 总结不能声称测试已经执行；结构覆盖也不代表执行通过。

## 三、样例与 Excel 模板使用不同 Profile

这一步刻意分开“写法样例”和“Excel 列模板”，避免把业务样例误当成模板规则。

### 3. 先创建独立的模板 Profile

在保存样例前，打开“Profile 与 Excel 模板”→“项目偏好”，点击“保存为新 Profile”，命名为“登录 Excel 模板”。此时原 Profile 还没有本轮样例，因此新 Profile 不会复制它。若此前已保存过样例，请在高级配置中把新 Profile 的 `sample_cases` 明确设为空数组并保存。

回到顶部 Profile 选择器，仍选原 Profile 作为“样例 Profile”。

### 4. 把用例写法只保存到样例 Profile

打开最终用例，选择一条质量较好的用例，点击“保存为项目样例”。目标选择最初的 Profile，点击“保存样例”。

预期断言：

- 提示“已保存到 <Profile 名称>”。
- 目标 Profile 版本递增；最多保存 5 条，新的选择会替换该 Profile 原有样例。
- 样例只教字段和写法，不成为业务需求依据。

### 5. 只把 Excel 模板应用到模板 Profile

把 `scenario-template.xlsx` 和 `case-template.xlsx` 分别上传，文件用途都选“格式模板”。复制：

```text
学习刚上传的场景模板和用例模板，只提取工作表、列和人工字段策略，应用到“登录 Excel 模板”这个 Profile；不要把模板里的示例业务当成需求。
```

若模型先只返回模板建议，点击“查看并应用 Profile 建议”，选择“登录 Excel 模板”，再保存。

预期断言：

- 场景模板与用例模板保持两套独立配置；应用一类不会擦除另一类。
- 人工备注/执行结果等人工字段允许为空，不由 AI 自动填写。
- 样例仍只存在于原“样例 Profile”，模板配置存在于“登录 Excel 模板”。

## 四、在同一对话中只读讨论成果

### 6. 用自然语言估算，不选任务快捷项

打开测试场景，使其成为当前结果；不要选“任务目标”，直接在聊天框复制：

```text
当前这些场景大概需要多少条用例？只估算设计工作量，逐场景说明范围、拆分理由和假设，不生成，不推进任何任务。
```

预期断言：

- 对话显示“用例数量估算”、总区间和逐场景区间。
- 来源行显示场景标题和精确版本。
- 场景版本号保持不变，没有新增用例，原 Run 状态/阶段不变。

### 7. 解释和只读评审实际步骤

打开最终用例，复制：

```text
用产品经理能理解的话总结当前用例，列出相关用例编号，并展开每条实际操作和预期结果；不要修改，不要声称已经执行。
```

再复制：

```text
只读评审当前用例的覆盖、步骤清晰度和预期结果，展示原步骤；只给意见，不优化、不保存修改。
```

预期断言：

- 回答引用真实用例编号；只读评审同时显示“用例步骤与预期”。
- 两次操作前后用例版本号完全相同。
- 评审文字区分“设计覆盖”和“测试执行”。

## 五、预览、应用与联动修改

### 8. 先做一项定向修改

在用例中只选一条，复制：

```text
只把选中用例的标题改得更明确，保留编号、步骤、引用和人工字段；先给我变更预览，不要保存。
```

预期：出现“变更预览”和“应用此修改/取消此修改”。预览阶段版本不变。点击“应用此修改”后只有该用例所在成果递增一个版本，未选条目逐字段不变。

### 9. 修改场景并同步关联用例

打开测试场景并只选目标场景，复制：

```text
把选中场景改为明确验证“登录成功后注销同账号其他活动会话”，并同步它关联的用例；其他场景和用例不要动，先预览。
```

预期断言：

- 同一个预览同时列出场景成果和关联用例成果；预览前后两者版本均不变。
- 点击“应用此修改”后，两份成果各产生新版本；未选场景、无关用例和人工字段保持原值。
- 已完成的主任务不会因为这次成果操作重新进入生成阶段。

若出现多套关联用例，系统应要求明确选择分支，不能猜测。

## 六、在原场景确认门上补资料、检查影响、同步后继续

本段建议演示前先预跑。目的是证明“成果讨论”和“原工作流确认”是两条边界清楚的控制线。

### 10. 建立一个仍在等待的原任务

打开当前测试场景，把 MODE 设为“人工确认关键节点”，复制：

```text
基于当前场景再生成一套测试用例，在场景确认处等我，不要自动越过确认。
```

预期：出现“确认场景，继续生成用例”。记下卡片展示的场景版本，但先不要确认。

### 11. 只读检查新增资料影响

直接在聊天框复制：

```text
先只分析这条新增规则对当前需求、场景和已有用例的潜在影响：登录成功后必须注销同账号其他活动会话。完整检查，不保存正文、不修改成果、不继续原任务。
```

预期断言：

- 回答明确“未修改成果”，列出影响摘要和依据。
- 需求、场景、用例版本及等待中的 Run 阶段不变。

界面会显示“新增资料影响分析”卡片：受影响需求、可能受影响的关联成果及其当前版本、已定位条目，以及需求与资料组合的检查进度。范围不完整、无法确定或需要按全部需求处理时，卡片会明确提醒人工确认；内部标识、内容摘要和版本指纹不会展示给演示用户。

### 12. 保存变更并更新需求与场景

再复制：

```text
现在保存这条新增规则，并只更新受影响的需求理解和场景，保留其他成果和原任务的停止条件；先不要继续场景确认。
```

预期：受影响的需求理解和场景产生新版本，原等待任务仍在场景确认。已有用例尚未同步时，打开“查看需求 → 场景 → 用例覆盖”，应显示场景已更新、关联用例仍基于较早版本。

复制：

```text
把刚才变更的场景同步到它关联的已有用例，保留人工字段和无关用例；先预览。
```

检查双成果预览后点击“应用此修改”。预期覆盖中的过期提示消失，需求 → 场景 → 用例编号仍连通。

### 13. 验证旧确认失效，再继续原门

资料更新或同步执行期间，“确认场景，继续生成用例”按钮应禁用并显示正在处理/保存。后端把确认绑定到 `interrupt_id`、控制版本和成果版本；旧页面或旧请求携带的场景版本会得到 409，不能越过门。

刷新到最新卡片后，确认卡应引用最新场景版本。点击“确认场景，继续生成用例”。

预期断言：

- 继续的是原 Run，而不是新建第三个任务。
- 生成模型收到最新场景；不会使用补资料前的旧快照。
- 原停止条件保留，任务完成后出现新的用例成果和总结。

说明：前端明确在“当前请求/修改处理中”禁用确认按钮；“旧版本确认返回 409 并刷新到新版本”的后端行为已有定向测试。不要宣称 UI 永久显示一个名为“确认已过期”的独立徽章，当前没有该组件。

## 七、覆盖、总结与真实 Excel

### 14. 查看覆盖并总结版本变化

打开最新用例，复制：

```text
展示当前需求、场景和用例的结构覆盖，指出缺口、孤立用例和过期关联；不要修改。然后用三句话总结这次新增规则带来的版本变化，不要声称测试已执行。
```

如模型需要先读取覆盖再总结，允许它分两轮完成。

预期断言：

- 显示“场景和用例覆盖”，包括需求已有场景、需求已有用例、场景已有用例和用例总数。
- 完整同步后不再提示需求/场景关联过期；若仍有提示，应回到关联分支检查，不能为了演示声称全覆盖。
- 覆盖是稳定编号和版本关系的结构统计，不等于业务需求完整，也不等于测试执行通过。

### 15. 分别导出场景和用例

打开测试场景，点击“导出”，Profile 选择“登录 Excel 模板”，点击“下载 XLSX”。再对最新用例重复一次；用例可分别演示“一条用例一行”和“一个步骤一行”。

也可直接复制：

```text
使用“登录 Excel 模板”这个 Profile，把最新测试场景和最新测试用例分别导出为两个 Excel 文件。
```

预期断言：

- 对话提供两个不同的真实下载链接，不是 JSON 或伪文件。
- 场景文件使用场景工作表名和场景列；用例文件使用用例工作表名和用例列。
- 打开 Excel 后能看到最新场景标题、用例标题、操作和预期结果；人工列未填写时保持空白。
- 冻结导出绑定成果 revision 与 Profile version；后续再编辑成果不会悄悄改写已下载文件。

## 八、现场验收清单

- [ ] 澄清建议可采用；采用后问题消失、答案保留在草稿。
- [ ] 保存、共享和继续是三个独立动作。
- [ ] 样例与 Excel 模板分别落在两个 Profile，互不覆盖。
- [ ] 自然语言估算、解释、只读评审不改变成果 revision 或 Run 阶段。
- [ ] 预览不写入；应用后才产生版本。
- [ ] 场景与关联用例能在一个预览中联动，未选内容不变。
- [ ] 新资料可先只读分析，再保存并定向更新；原确认门保持等待。
- [ ] 修改处理中确认按钮禁用；后端拒绝旧版本确认。
- [ ] 覆盖能显示缺口和过期，不能冒充执行结果。
- [ ] 场景和用例分别下载为可打开的 XLSX，单元格是最新内容。

## 已知演示缺口与不要做的声明

1. `tests/test_framework_http_v270.py` 已验证九轮自然语言 HTTP turn 的框架执行，但语义 action 是可控模型给出的；真实模型路由准确率尚未由该测试验证。
2. 只读资料影响已有专门的前端卡片，但卡片只展示业务可读的影响范围、关联成果和检查进度；内部追踪字段不会显示。
3. 当前“补充资料”弹窗会直接调用更新能力，不是只读影响预览。需要“先看影响”时必须先发第 11 步自然语言提示，再明确发第 12 步保存/更新提示。
4. `ProjectSupplement` 当前默认更新需求理解与场景，不会自动同步已有用例；用例同步必须另行明确请求。
5. 前端在操作进行中禁用确认，后端拒绝 stale revision；不要宣称已有独立“确认已过期”徽章。
6. 模型可能因业务事实充分而不产生澄清问题；框架支持澄清卡不等于每次输入必然出现澄清。
