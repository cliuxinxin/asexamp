# TCG 3.0.11 演示与验收

本版保留红色对话界面和原来的输入框选项。修改预览在 AI 消息里接受/拒绝；Profile 更改仍有专门的查看确认入口。建议用同一项目的两个新会话分别演示完整主流程和跳过场景，避免为了展示分支反复重置正在确认的任务。

## 准备

启动新版，完成“模型与设置”中的原生工具调用连接测试。选择“人工关键节点/逐步确认”和“自动识别”。上传一份需求文档，或明确将下面文字作为本轮需求：

> 登录成功进入首页。连续输错密码五次后锁定账号十分钟。被停用的账号不能登录。管理员可以停用账号；对于停用前已经登录的会话，业务需要确认是在停用时立即失效，还是下一次访问时失效，只支持这两种处理。

模型返回内容可能不同。按钮只来自本轮实际生成的明确选项；开放问题使用完整建议答案，不凭空变成“是/否”。演示前预跑一次以核对你使用的模型能否按提供的工具 Schema 返回选项。

## 会话 A：完整流程、就近回答、内联修改、追溯

| 步骤 | 操作或在对话框发送 | 应看到什么 |
| --- | --- | --- |
| 1 | “根据这份需求生成测试用例，逐步确认，并包含评审。” | 先生成需求理解；仍可按需打开需求表格和三张业务图。 |
| 2 | 对“已有会话何时失效”点击问题下方的一项完整答案。 | 仅提交本题，不确认需求理解；被采用的按钮消失，其他未答问题保留。提前输入的草稿保留。 |
| 3 | 回答剩余问题，随后发送“确认这版需求理解，继续生成场景”。 | 进入场景生成并停在场景确认。回答澄清和确认理解是两个动作。 |
| 4 | 打开场景表格，选中一条后发送“只修改这条场景的标题为‘验证停用账号访问控制’，其他内容保留”。 | AI 消息显示修改摘要和字段前后差异，底部有“接受 / 拒绝”。未接受前成果版本不变。 |
| 5 | 先“拒绝”，再提出同样修改并“接受”。 | 拒绝保留原场景；接受产生新版本，仍等待场景确认。长差异可以点“再查看”或展开更多字段。 |
| 6 | “确认当前场景，继续生成用例并评审”。 | 用例保存后直接产生评审建议，不再单独要求确认用例草稿。评审意见、依据和修改差异显示在消息内。 |
| 7 | 可先输入“解释第一条评审意见”，再点击当前评审卡片“接受”。 | 提问不会应用建议；接受后修改用例并完成流程。若选择拒绝，则保留原用例、结束本轮评审。 |
| 8 | 点击侧栏“追溯矩阵”。 | 默认本会话，树表显示需求 → 场景 → 用例，可展开、筛选缺口/待同步/N/A，点击条目查看对应成果。 |
| 9 | 返回对话，打开一个场景，选中并要求只修改标题；接受预览，暂不继续下游生成。再打开矩阵。 | 旧用例仍显示其实际使用的场景版本及“待同步”。没有关联的节点显示缺口，独立 N/A 条目单独标注。 |
| 10 | 回到对话说明要继续更新相关用例，按实际出现的当前确认提示回复。 | 主流程使用更新后的上游版本；更新完成的条目不再标为待同步。不会因为浏览矩阵而修改数据。 |

表格中的具体编号以实际生成结果为准。对话指代不清时，先在成果表格选择条目再提出修改，可确保目标明确。每次同意只针对当前显示的一个对象，不会一口气确认后面的环节。

## 会话 B：跳过场景与只要草稿

在同项目新会话上传/指定需求，并发送：

> 根据需求生成用例；先让我确认理解。

在“确认需求理解”时发送：

> 跳过场景，直接根据当前需求生成用例草稿，不要评审。

应直接保存用例并完成：没有新增场景，也不进入评审。打开用例，关联处显示“场景：N/A（已跳过）”和真实需求；追溯矩阵直接连接需求与用例。

也可以第一句就说：

> 这次跳过场景，只根据需求生成用例草稿，不评审。

人工模式仍会先确认需求理解。若希望保留评审，只说“跳过场景，直接生成用例并评审”；用例后仍显示待接受的评审建议。未解答的澄清不会因跳过场景而自动变成已确认规则。

同项目切换矩阵范围为“整个项目”，可同时查看两个会话；同名编号按实际成果区分。原有场景用例切换到直接需求生成时建立新的用例分支，旧分支及人工记录保留。

## 提示词外置演示

1. 用文本编辑器打开 `backend/tcg/prompts/chat.yaml`。
2. 在 `system: |` 下保持缩进，增加一句回复风格要求，例如 `Keep final replies to at most three short sentences.`，保存。
3. 不重启服务，在对话中请求“总结当前用例，按你现在的回复规范回答”。下一次调用读取新提示词；措辞效果由实际模型决定。
4. 查看对应调用日志中的 `prompt_templates` 和 `system_prompt_sha256`，确认文件、键及内容指纹已变化。
5. 恢复原文字。已有成果不会因为改 YAML 自动变更。

其他生成、评审、修改、三图等提示词及规则见 [PROMPTS.md](PROMPTS.md)。YAML 调整的是模型指令；证据验证、工具权限、版本确认仍由程序执行。

## 继续验证原有功能

- 场景与用例仍可打开表格手动编辑、AI 修改，并导出 Excel。
- 例如“给当前用例增加测试数据列，并导出修改好的 Excel”：先查看并接受当前用例修改，随后查看和确认对应 Profile 更改，保存的导出请求在 Profile 确认后完成。
- 需要导出直接用例的需求编号时，可在 Profile 中添加 `requirement_ids` 列；空场景编号保持空值，真实需求编号可导出。
- 明确的项目澄清可在“项目知识库”查看；未采用选项不进入共享事实。
- 生成校验失败仍最多带原因修复三次；最终未合格的内容作为待核对草稿展示，不冒充已确认成果。

本版验证使用本地可控模型响应、真实 HTTP/SQLite/LangGraph 检查点及前端组件交互。尚未连接你的实际 Azure/内网部署，演示前应使用该部署预跑上述流程。
