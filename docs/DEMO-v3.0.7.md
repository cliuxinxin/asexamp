# v3.0.7：对话补充、直接改 Profile 与引用修复

沿用原来的红色对话首页。对话由原生 Tool Calling 选择动作，LangGraph 继续管理生成顺序和人工确认点。

## 一次演示完整过程

1. 上传简单登录需求，选择逐步确认，发送：**根据上传需求生成测试用例，逐步让我确认。**
2. 确认需求理解，等待场景出现。发送：**这些场景预计需要多少条用例？先只估算。** 应返回估算，保持当前场景确认点。
3. 发送：**增加一个并发登录场景：同账号第二次登录后，第一次登录的会话必须失效。** 系统准备修改预览。没有现成需求项时，预览中会同时出现“对话补充需求”，内容保留你的原话；已有场景保持不变。若希望挂到指定需求，明确写出其编号。
4. 发送：**同意应用这次新增。** 原话成为真实补充资料，需求关联和场景作为一个事务保存。系统仍停在场景确认点。通过“查看当前成果”核对场景及其需求关联，然后发送：**场景确认，继续生成用例。**
5. 用例草稿出现后，确认进入评审；查看评审意见，再确认完成。也可先说明修改意见。确认修改与确认进入下一阶段仍是两次不同的确认。
6. 发送：**导出格式增加一列执行状态，字段名 status，人工填写。** 不需要上传模板。对话总结更改，输入框上方出现“查看 Profile 更改”。可以打开比较并确认，也可以回复 **同意应用 Profile 更改**。
7. 打开当前用例成果，点击 **导出 Excel → 下载 XLSX**。当前成果默认选用刚确认的 Profile，新增执行状态列允许留空。历史版本默认保留生成时的配置快照；也可在导出窗口明确选择其他 Profile。
8. 发送：**解释并总结这些用例测试了什么。** 回答显示在聊天中，不修改用例，不重新生成。

还可测试这些自然问法：

- **在场景 SC-001 下增加一个边界用例，具体要求是……**：复用指定场景，以你的原话作为补充依据；缺少明确预期时，不编造通过条件。
- **把执行状态列改名为测试状态，再加一列执行人。**：继续修改待确认的 Profile 草稿，不丢失先前的列建议。
- **导出时不要 refs 列，但保留内部引用。**：只修改导出列，成果内部溯源仍在。
- **补充一个规则：……，据此修改所选用例，先让我看修改。**：准备含对话证据的修改预览，应用后保存新版本。

## 本次错误如何处理

旧版本的原生调用会修复参数结构，但随后执行的业务引用校验没有专项修复，因而一个无效引用可能让当前批次失败。

现在分两种情况：

- 条目仍有本批有效引用：去掉无效的附加引用，在成果说明中记录处理情况。
- 条目全部引用无效：只请求修复这些条目的引用，要求使用本批真实证据 ID 并返回原文片段。已有业务字段、步骤、预期、稳定编号保持不变。

修复仍没有业务依据时，当前批次不会作为有效成果发布。系统明确列出相关条目，保留已有成果、已完成批次和运行中的未发布候选；重试当前步骤时复用候选，只修复未解决引用。补充资料造成输入变化后，则按新输入重新处理相应工作。普通修改预览失败不宣称保存了尚未发布的草稿。

不要通过清空 refs 或删除必要用例来绕过校验。错误中的“实际 string”表示数据类型，不一定表示模型字面返回了 `"string"`。

## 对话、证据与确认

- AI 的公开操作说明和最终回复显示在同一条助手对话中；私有推理和工具参数不展示。
- 工具失败后即使继续读取配置，具体错误也不会被读取成功的提示盖掉。
- 对话补充使用本次真实用户原话，模型不能用自己编写的说明冒充用户证据。仅提问、估算、查看或改表头不会生成业务证据。
- 自动补上的父级明确标注为对话补充，属于可查看的正式关联记录，不代表模型额外发现了业务规则。预览关闭或未确认时不写入资料和成果。
- 对话新增用例会保留原有导入用例；不会为了补新条目的关联而改写旧用例。
- 明确的项目澄清仍可要求保存到项目供同项目会话使用；本次普通成果追加的补充资料默认属于当前会话。

## 实现边界

新增 `read_profile_tool` / `modify_profile_tool`，复用已有 Profile 差异与版本确认服务，不需要二次模型调用。`modify_artifact_tool` 增加 `add`、`parent_id`、`use_dialogue_evidence` 参数，服务端负责证据和父级的原子提交。引用修复是有限的专用调用，不重写整批用例。新增请求只发送目标父级、相关证据和现有编号；完整前后对比保留给界面，聊天模型只接收变更摘要。没有增加旧式意图控制器或额外的对话锁。

本地通过可控模型响应验证真实 HTTP、SQLite、原生工具调用、人工/自动图流程和 Excel 单元格内容。尚未验证你的实际 Azure/内网模型对不同自然表达的识别质量。

## 升级

停止旧服务，保留原数据目录，将新版解压到新目录启动：

```bash
python start.py --data-dir /path/to/existing/data
```

保留原模型配置。无需删除项目或重新建会话。旧失败任务在原始候选未被保存的情况下，第一次重试仍需要重新取得该批模型输出，之后才可采用本版引用局部修复。
