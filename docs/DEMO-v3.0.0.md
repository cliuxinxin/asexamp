# v3.0.0：同一个聊天框测试全部要点

> 本文件记录原版本交互。v3.0.10 已取消用例草稿确认，改为先生成评审建议、确认后应用修改；当前演示请使用 [v3.0.10 步骤](DEMO-v3.0.10.md)。

先在模型设置中执行连接测试，确认实际模型和网关支持 Tool Calling。沿用原来的开始页、红色强调和输入框选项；下面的业务指令都直接输入聊天框。表格用来查看内容，也可以勾选条目辅助限定范围。

## 准备

新建项目和对话，选择 Human。上传 `examples/conversation-v290/login-requirements.md`，作为需求正文。该文档故意没有写锁定时长，适合演示澄清。同项目已有的已确认规则可能让模型无需再问同一个问题。

编号和实际问题由模型生成。以下涉及编号的文字请替换为页面实际编号；没有出现问题时直接从需求理解确认开始。

## 第一轮：理解、澄清、场景、用例和评审

| 步骤 | 聊天框输入 | 检查结果 |
| --- | --- | --- |
| 1 | 根据上传资料生成测试场景和用例，每一步都等我确认。 | 生成理解；如需澄清，显示每个问题及建议假设。此时没有用例。 |
| 2 | 锁定10分钟，期满自动解锁。这是已确认的项目规则，请保存到项目。 | 更新理解，已答问题收起；仍等待确认更新后的理解。如还有问题，继续在聊天中回答。 |
| 3 | 同意，继续。 | 生成场景并等待确认。场景行能看到对应需求。 |
| 4 | 这些场景大概需要多少条 case？只估算，不生成，也不要继续。 | 返回数量区间、理由、假设；场景版本与确认位置不变。 |
| 5 | 解释登录成功场景的需求依据，先不要修改。 | 解释内容和依据，保持场景确认。 |
| 6 | 把登录成功场景标题写清楚，不改变业务规则，先给我看预览。 | 展示修改前后内容；正式版本不变。对象不明确时直接回复真实编号。 |
| 7 | 同意采用这次预览。 | 场景只增加一个版本；仍等待确认场景，不生成用例。 |
| 8 | 同意这些场景，继续生成用例。 | 用修改后的场景生成用例草稿，等待确认。表格显示前置条件、step、expected result、场景和需求。 |
| 9 | 只修改用例 TC-实际编号 的标题为“验证有效凭证登录后进入首页”，保留步骤和预期，不继续。 | 只有指定用例标题变化；稳定编号、其他用例和人工数据保留。 |
| 10 | 同意当前用例，开始评审。 | 评审完成后再次等待确认；可在表格查看步骤、预期和评审信息。 |
| 11 | 总结本次评审发现的问题，再向业务人员解释登录用例验证什么，不要修改或结束任务。 | 解释和总结；保持评审确认位置。 |
| 12 | 同意评审结果，完成本轮。 | 当前任务完成；没有持续显示已处理的问题。 |

如果建议答案确实合适，步骤 2 也可回复“同意采用建议答案”。模型给出的假设需要实际核对，系统不会把未经采用的建议自动当作确认事实。

## 第二轮：已有场景和用例后补需求

| 步骤 | 操作或聊天输入 | 检查结果 |
| --- | --- | --- |
| 13 | 上传 `examples/conversation-v290/login-audit-supplement.md`。 | 只增加资料，成果不自动变化。 |
| 14 | 这份登录审计文档是补充需求。先更新需求理解，等我确认，再更新关联场景和用例。 | 保存新的理解，原任务回到理解确认；已有场景、用例暂不改动。 |
| 15 | 同意新的理解，继续。 | 更新相关场景，等待确认；场景行仍有对应需求，用例关联能看到待同步情况。 |
| 16 | 只估算现在这些场景需要多少条用例，不生成。 | 回答估算，保持当前确认位置。 |
| 17 | 同意场景，继续。 | 更新关联用例，步骤/预期体现审计补充；等待用例草稿确认。 |
| 18 | 同意当前草稿，继续评审。 | 评审后再次等待确认。 |
| 19 | 同意，完成。 | 同一业务循环完成。 |

同样的补资料与回改可在第一轮任意人工确认点进行。上传本身不表示采用；明确指定更新理解、场景或用例。如果只要求改当前场景，不会顺带修改需求理解；下一步如何继续由当前确认提示说明。

## 模板、导出、样例与项目复用

1. 上传 `examples/conversation-v260/scenario-template.xlsx` 和 `case-template.xlsx`，用途为模板。输入“学习这两份场景和用例模板，先给我建议”。看到模板建议后回复“同意”。检查 Profile 的两类列定义各自保留。
2. 输入“按当前 Profile 补全现有用例缺少的模板字段，已有字段与人工执行数据不要修改”。查看缺失列补全或具体缺依据原因；不重新理解需求。补全保存后的当前成果仍可再确认。
3. 输入“按当前 Profile 分别导出全部场景和用例为 Excel”。从聊天回复下载文件，核对表头、列顺序、步骤和预期、自定义列。
4. 输入“把 TC-实际编号 这条用例保存为当前项目 Profile 的格式样例”。检查 Profile 样例；它只指导写法与格式，不成为新项目的业务需求或引用。
5. 在同项目新建对话，输入“列出本项目已确认的账号锁定规则及来源”。应能读取 10 分钟和期满自动解锁的已确认澄清。新对话生成同类需求时可使用这份项目资料。

同项目多人复用需要连接同一后端服务，当前没有新增成员账号系统。

## Auto 和明确停止范围

另建对话，选择 Auto，上传需求，输入“自动完成理解、场景、用例和评审”。没有必要澄清时自动完成；有必要澄清时仍会询问。运行中可说“当前步骤完成后暂停”；看到暂停提示后再修改或继续。

仅要场景时，新对话输入“只生成场景，不要生成用例”。Human 确认场景后任务按范围结束；估算仍是直接聊天提问，不需要选择一种任务模式。后续要生成用例，明确指定现有场景继续；不要把“同意”解释为自动扩大原任务范围。

## 如何判断演示是否通过

核心检查是：每条消息作用于当前对象；一条“同意”只消费一个待答提示；提问不改产物；修改后仍需确认；下一阶段使用最新父成果；范围和人工数据不被扩大或覆盖。

本版自动化验证控制模型返回的原生工具调用，验证真实 HTTP、数据库和图行为。实际模型如何理解自由表述仍需预跑。连接测试通过不等于所有业务问法都已经在你的网关验证过。
