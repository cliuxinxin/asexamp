# v3.0.11 实施边界

在 v3.0.10 原生 Chat Agent / Pipeline 分离基础上完成本次用户已指定的五项改动，保持红色对话主界面和紧凑初始输入框。

1. **生成路径**：正常经过需求理解、场景、用例、评审。明确要求“跳过场景”时，真实图边从需求确认进入基于需求的用例生成；用例保存真实需求关联，场景注明已跳过，不创建虚拟场景。只要草稿时完成生成即可结束。恢复、重试和历史版本仍使用现有检查点与版本契约。
2. **消息中的差异**：当前修改建议位于产生它的 AI 消息内，精简展示字段对比，底部接受/拒绝；需要更多内容时在卡片内展开。接受只消费当前建议。历史卡片只读，版本过期无法应用。评审拒绝保留正式用例，不应用建议。
3. **问题旁的选项**：只显示明确提供的结构化选项，二选一问题可直接回答；普通开放问题不会被推测成 Yes/No。点击后只提交当前题，保留输入草稿。仅成功采用后收起该题按钮，其他问题仍可回答。
4. **追溯矩阵**：侧栏独立入口，默认当前对话，可查看整个项目。根据保存的真实成果关系构建树表，显示缺少上下游、待同步、独立条目及跳过场景的直接用例。相同业务编号在不同成果中分别统计；多父关联展示可重复，但统计按唯一成果条目去重。矩阵只读，不消耗模型调用，不自动打开。
5. **外部提示词**：固定系统指令与业务提示放入 YAML，用安全加载器按模板键读取。无任意模板代码执行；缺失或损坏时提示具体文件和键。业务数据校验、项目范围、版本守卫和确认规则保留在 Python。请求日志记录实际提示词及模板来源/摘要哈希，便于调试。

验收沿完整对话链路检查：正常 Human、跳过场景并评审、直接草稿、澄清选择、内联修改接受/拒绝及过期、追溯缺口与待同步、Profile 确认后的 Excel 导出，以及提示词修改/加载失败。使用可控模型响应验证真实 HTTP 和图行为；真实模型自由语言识别能力需在用户服务预跑。
