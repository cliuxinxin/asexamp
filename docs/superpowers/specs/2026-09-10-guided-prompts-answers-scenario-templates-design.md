# TCG v2.5.8 引导提示、澄清建议与场景模板设计

## 目标

让用户选中任务后可以直接发送，在澄清节点可以一键采用有依据的 AI 建议答案，并让测试场景与测试用例都能分别学习模板和导出 Excel。

## 交互设计

### 任务引导提示

前端为每个明确任务维护一条可编辑的默认提示词。点击“学习模板”时填入：

> 请学习已上传的 Excel 模板，自动判断是场景模板、用例模板或同时包含两者，提取工作表、列顺序、字段定义、填写方式和文件名规则。

只在输入框为空，或仍是上一个任务的默认文本时替换，不覆盖用户已编辑的草稿。

### 澄清建议答案

需求理解结果保留现有 `report.questions: string[]`，并可选返回：

```json
{
  "question_suggestions": [
    {
      "question": "问题原文",
      "answer": "建议答案",
      "basis": "为什么可以这样回答",
      "refs": ["exact evidence id"],
      "confidence": "supported"
    }
  ]
}
```

`supported` 表示答案可由需求证据支持；`assumption` 表示只是建议假设。服务端校验问题必须存在、答案非空、引用必须来自本轮非示例证据；无可靠答案时不生成建议。

前端每个问题显示建议答案、依据说明和“采用此答案”。用户可一键填入全部建议，再直接提交或修改。采用只是填入草稿，不自动跳过人工确认。

## 场景模板与导出

Profile 保留现有用例配置，新增互不覆盖的场景配置：

- `scenario_excel_columns`
- `scenario_sheet_name`
- `scenario_filename_pattern`

场景默认列为 `id`、`title`、`description`、`priority`、`requirement_ids`、`refs`。其中 `requirement_ids` 和 `refs` 作为场景追溯字段允许导出，但不放宽用例模板字段的安全校验。导出仍执行公式注入防护、工作表名清理、选中范围校验和自动换行。用例导出的 `excel_columns`、`sheet_name`、`filename_pattern` 保持不变。

“学习模板”响应顶层新增 `template_kinds: ["scenarios"|"cases"]`，只标识本次识别结果，不写入 Profile。模型可同时提议场景列和用例列；只识别到一种时，只更新该种建议，另一种沿用当前 Profile。业务样例值仍不得被当成可复用需求。

## 数据与兼容

所有新 Profile 字段都是可选字段。旧 Profile 缺少它们时使用场景默认值，不进行数据迁移。模板学习仍返回 proposal，由用户选择保存到现有 Profile、新建 Profile 或仅本次使用。

## 错误处理

- 场景模板列无效时显示具体字段，不影响已有用例配置。
- 建议答案引用无效时丢弃该建议，仍显示原澄清问题供人工输入。
- 场景导出只读已保存 Artifact，不调用模型；模板学习失败不修改 Profile。

## 定向验证

1. 任务按钮填充提示，且不覆盖用户草稿。
2. 有证据建议可一键填入和提交；无建议仍可手动回答。
3. 旧的字符串问题输出仍可正常暂停。
4. 场景默认导出、自定义列导出、选中导出均生成可读 XLSX。
5. 学习场景模板只修改场景配置，学习用例模板只修改用例配置，同时存在则两者都保留。
6. 旧 Profile 与现有用例导出行为不变。
