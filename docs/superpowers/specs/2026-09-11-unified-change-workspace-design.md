# TCG v2.8 统一成果工作区与修改闭环

目标：用户在任意阶段修改场景、需求理解或补充资料后，始终知道当前保存了什么、哪些结果待更新、下一步做什么。延续已授权的前后端改造，使用现有项目、版本、LangGraph 和预览事务，不引入另一套工作流或存储。

## 交互约定

主页面固定为成果工作区与右侧聊天。需求理解、场景、用例、评审四个阶段可切换；同一时刻只有一份完整可编辑成果。聊天展示短回执和按需展开内容；编辑、历史、样例、模板、日志按使用频率分层。

工作区只有一处主操作：处理中显示进度；有澄清先回答；有预览先应用或放弃；上游变更先预览更新受影响成果；输入一致后才显示原人工确认。切换查看历史阶段不改变正在确认的任务。

覆盖分成两件事：关联覆盖说明“有没有对应条目”；更新状态说明“条目是否仍符合最新输入”。默认突出后者，例如“需求理解已更新，3 个场景、8 条用例待更新”。数量从真实关联计算，缺少关联不伪称已覆盖。

上传资料只登记待使用资料。明确要求采用后，先预览需求理解变化，再同步所授权的已生成后续成果。已提交的澄清应更新需求理解条目和相关说明，不只存一段答案。全新需求可以新增有依据的稳定条目，不要求必须匹配旧需求。

## 后端边界

- workspace_changes.workspace_state：从当前分支、来源、预览、版本和等待任务导出共同状态，供界面与聊天使用。
- workspace_changes.prepare_reconciliation：从最早变化的已保存上游成果准备下游更新，复用 artifact_actions 的内存草稿与原子应用。
- conversation_project.preview_from_sources：先分析新资料并准备理解更新，区分已有规则变化、全新规则与无影响来源确认。
- requirement_refresh.refresh_clarification：针对已提交答案局部更新理解，一次模型调用，复用已完成提交以支持检查点重放。
- artifact_actions.rebind_waiting_runs：所有手动、恢复、聊天修改共享输入缓存/版本绑定，不自动推进。
- workspace_changes.assert_current_inputs：继续当前步骤前检查它真正要使用的上游输入，不能仅检查当前成果自身 revision。

兼容既有能力名，新增 workspace.reconcile 作为统一的“更新受影响成果”入口。仍使用 artifact.apply / discard 应用与放弃。保存后的影响状态由持久版本计算，刷新页面不丢失。

## 验收边界

场景局部修改→显示准确受影响用例→预览→原子应用→回原确认点；理解修改→旧场景禁止直接继续→同步→继续；新资料含新增规则→理解新增条目→下游补齐；澄清答案进入真实理解；无关条目、人工字段和历史版本保留；Auto 不使用已过期输入继续。源代码与组件测试和真实浏览器视觉验收分开说明，访问受限时不声称视觉验证通过。
