# v2.5.12 工作区与演示实施计划

目标：让项目澄清复用、结果微调与联动、覆盖核查成为明确可演示的操作。

设计：沿用当前 LangGraph 生成流程和稳定 Artifact ID。项目共享来源保留真实证据引用；格式样例只进入格式上下文。新增产物操作服务保存预览，应用时原子比较输入版本，联动修改只触及真实关联场景的用例。历史 Artifact 和旧 run 保留。

1. 项目资料：`project_context.py`，接通确认澄清共享、Profile 样例快照、等待节点补资料后继任务；验证跨会话复用和旧来源保持可追溯。
2. 产物关联与覆盖：`workspace_coverage.py` + Store.artifact + 确认节点保存明确父版本；按 requirement_ids/scenario_id 展示结构覆盖、缺口和过期关联。旧产物没有 lineage 时明确选择关联对象。
3. 产物操作：`artifact_actions.py`，estimate/explain/modify/sync 预览及原子应用；校验范围、引用、schema、并发和人工字段。估算仅返回区间与假设，绝不进入用例生成。
4. 前端：`ArtifactActions`、`WorkspaceCoverage`、项目资料与补充弹窗；步骤/预期展开、微调预览、阶段打开最新版本、显式问答目标。
5. 演示：准备登录业务需求、后续变更和样例 CSV；逐项写操作、预期、是否调用模型与当前能力边界。
6. 验证：只跑变更对应的标准库逻辑检查、DOM 交互和生产构建。缺少 FastAPI/LangGraph 依赖时不宣称真实集成通过；不运行全量历史测试。
7. 交付：版本 2.5.12，排除数据与依赖目录打包，生成 manifest 并检查压缩包，保存最终下载文件。

团队分工：项目后端、产物操作后端、关联覆盖后端、产物前端、项目前端并行；主线程负责接口整合、演示文档、版本构建与交付。
