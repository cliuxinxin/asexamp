验证日期：2026-09-12。结果：本次执行的 3 项测试通过，耗时 5.00 秒。

## 验证方式

启动生产 `create_app`，通过本地真实 HTTP socket 调用 API，使用真实 SQLite Store、成果版本和 LangGraph 执行/确认节点。需求附件经上传接口解析，补充资料经文本资料接口保存。测试未直接创建或修改数据库中的任务、成果、检查点或确认节点；数据库只读检查用于确认历史与内部采用范围。

聊天请求仅包含自然语言、模式和可见对象/选择上下文，不发送 `command`、`intent` 或 `intent_hint`。测试模型返回受控的路由决策和业务内容，因此本轮验证的是对话能力执行、数据传递及流程状态，不能证明真实模型对各种自然语言说法的识别质量。

## 连续人工链路

同一项目、同一主任务从上传需求运行到确认完成；另一个对话仅用于验证项目事实复用。

| 环节 | 已通过的实际断言 |
| --- | --- |
| 人工启动 | 需求理解后停在澄清节点，场景和用例尚未生成 |
| 采用当前答案 | `clarification.adopt` 的 `submit:true` 在同一轮提交、共享并更新相关需求理解；没有重新调用需求分析 |
| 理解刷新 | 只有锁定规则改变，原正常登录需求保留；答案来源加入引用，已回答问题移除；随后停在理解确认 |
| 项目共享 | 同项目新对话通过规则列表及问答读取同一确认来源；原任务和所有成果不变 |
| 理解确认 | 显式继续后生成场景，并停在场景确认 |
| 只估算 | 返回分场景估算及合计范围；未创建 case，任务状态和成果版本不变 |
| 局部修改场景 | 选中标题按要求保存新版本；其他场景和需求不变；仍停在场景确认 |
| 用例草稿 | 确认后使用修改后的场景版本生成用例；停在用例草稿确认，尚未调用 AI 评审 |
| 未采用附件 | 上传两份补充资料后，确认入口仍可用；用例不变，新资料没有自动进入任务来源 |
| 指定资料只改 case | 仅指定的补充进入修改上下文；另一附件被排除；只更新所选 case 并保留既有步骤和其他用例 |
| 上下游差异 | 需求与场景的内容和版本保持不变；关联数据保留具体 case、补充来源与父级的待同步提示 |
| 完整用例信息 | 读取结果包含真实配对的操作步骤与预期结果 |
| 评审与完成 | 显式确认草稿才评审，之后停在最终确认；补充后的步骤和上游差异保留，不把上游伪装为已更新 |
| 完成后解释总结 | 从当前用例解释审计检查；任务、成果和历史不变，没有另起任务或重新生成 |

主任务结束时，需求分析、场景生成、用例生成、AI 评审和最终总结各调用一次；局部修改和澄清刷新没有重跑完整生成链。
