# v2.8.0：在同一个工作区处理变更

本轮演示持续使用同一个任务。页面中央的 **测试设计工作区** 通过 **需求理解 / 测试场景 / 测试用例 / 评审** 切换当前成果；顶部统一展示待处理变更、影响范围和下一步。聊天用于解释、提出修改和补充信息，历史回复保留当时的记录。

## 准备

1. 新建对话，选择 **Human · 逐步确认**，点击 **添加需求文档**，上传 `examples/manual-v271/login-requirements.md`，用途选择“需求正文”。
2. 发送：“基于上传需求生成测试场景和用例，缺失规则先澄清，每个关键节点等我确认。”
3. 如需澄清锁定时长，填写“连续失败五次后锁定 10 分钟，期满自动解锁。”，保存并继续。到达需求理解确认后，检查需求条目本身、引用与业务图已体现已确认的答案。
4. 确认需求理解，生成场景；再确认场景，生成用例草稿。任务应停在用例草稿确认，尚未开始 AI 评审。

现场使用实际模型时，请先预跑一次；问题措辞、条目数量与编号可能不同。

## 故事一：改了场景，已有用例跟着更新

1. 在中央切换到 **测试场景**，点击 **编辑**。把有效登录场景的说明改为：“设备 B 登录成功后，设备 A 的活动会话必须立即失效。”点击 **保存新版本**。
2. 查看顶部待处理变更，再点 **查看受影响范围**。应列出该场景关联的用例；其他场景和用例保持原样。任务仍在用例草稿确认，需要先处理变化才能开始评审。
3. 点击 **预览更新受影响内容**。检查预览读取了刚保存的场景，更新关联用例的步骤与预期。预览期间，已保存用例仍是原版本。
4. 点击 **应用更新**。用例产生新版本；刚才保存的场景不会再被重复修改。顶部回到可确认状态，仍停在用例草稿确认。
5. 打开 **测试用例**，检查“设备 A 的活动会话立即失效”已进入预期结果。确认最新草稿后开始 AI 评审，评审结果仍等最后一次确认。最后确认评审结果，完成原任务。

## 故事二：返回需求理解修改，继续使用已有场景

另开一个对话，按准备步骤运行到场景确认。

1. 切到 **需求理解**，点击 **编辑**，把有效登录规则改为：“有效凭证登录成功后，必须立即注销同账号的其他活动会话。”点击 **保存新版本**。
2. 顶部应显示已有场景受影响。此时不能直接确认旧场景并生成用例。
3. 点击 **预览更新受影响内容**，检查受影响的场景说明；再点 **应用更新**。
4. 切回 **测试场景**。原场景成果已产生新版本，登录规则已更新；错误凭证等无关场景保持原内容。任务仍停在场景确认。
5. 确认最新场景后才生成用例草稿。草稿应使用最新的登录规则；整个过程仍是同一个任务。

## 故事三：新资料带来一条全新需求

可接着故事二，在确认场景之前操作。新建一个文本文件 `admin-session-change.md`，内容为：

```text
管理员可以主动撤销指定用户的所有活动会话。
```

1. 点击 **添加需求文档**，上传该文件，用途选择变更资料。顶部应提示资料待纳入。
2. 点击 **预览更新受影响内容**。检查预览新增了“管理员撤销会话”需求，并为它补充场景；已有需求与场景不应因新增规则而全部重写。
3. 预览中的新增需求应引用新资料。确认后点击 **应用更新**；新需求与关联场景保存，顶部的待处理状态清除。
4. 切换 **需求理解** 与 **测试场景**，检查新增条目和关联。随后确认最新场景，生成的用例草稿应包含管理员撤销会话的覆盖。

也可以在打开 **测试场景** 时直接发送：“管理员可以主动撤销指定用户的所有活动会话。请预览关联需求和场景的更新，保留当前确认节点。”这会保存补充规则，并预览需求理解及场景的修改；点击 **应用更新** 后才保存成果。

如果预览范围不合适，点击 **取消此次更新**，补充说明后重新预览。取消预览保留已保存的编辑和新资料；它们仍需要处理。

## Auto 对照与验收范围

另开新对话，选择 **Auto · 自动完成**，上传原始需求并请求自动生成。正常路径仍依次产出需求理解、场景、用例与评审并完成。已有成果发生变化时，先按工作区提示处理受影响内容，再继续原任务。即使另开一轮 Auto 使用已有场景，只要这些场景尚未同步需求变化，也会先暂停；预览并应用更新后，明确继续才生成新用例。

聚焦验收命令：

```bash
python -m pytest -q tests/test_change_journey_v280.py
```

六条测试覆盖：场景编辑后阻止旧用例进入评审、预览与应用后完成原任务；需求编辑和新增独立需求更新已有场景；已确认澄清进入需求条目再传给场景和用例；聊天补充规则先预览，重复请求不重复保存资料；Auto 原路径仍可完成；新一轮 Auto 也不能直接使用过期场景。测试使用真实 HTTP、LangGraph、上传、版本与确认请求，只控制模型响应。它们验证执行契约；浏览器操作与实际模型表现需要按上述步骤另行验收。
