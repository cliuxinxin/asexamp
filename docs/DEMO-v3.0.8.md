# TCG v3.0.8 演示与复测

保留原有红色 UI、初始居中输入框、输入框附近的任务选项和对话确认流程。AI 回复、公开说明及成果附件统一在浅灰气泡中；打开成果后仍使用宽表格。没有额外模型调用来判断字段漂移、生成 Profile 差异或显示规则来源。

## 一次串联四项改动

使用一个专门的演示项目。在原版本数据目录继续运行即可，无需清空数据。启动方式与原版一致：`python start.py`。真实模型应支持原有的原生 Tool Calling。

### 1. 保存项目澄清

在会话 A 输入：

> 已确认项目规则：账号连续五次登录失败后锁定十分钟，时间到后自动解锁。请保存为项目澄清，让同项目其他人复用。

等待保存完成，打开页面顶部的“项目知识库”。应看到规则内容、来源对话、日期和来源版本。“取消共享”会停止项目后续复用；此步骤先保留共享。

### 2. 在新会话中观察历史规则和气泡

同项目新建会话 B，选择“Human · 逐步确认”。上传包含以下内容的 TXT/Markdown 文档，标记为需求：

> 注册用户输入有效账号密码后登录成功。无效密码登录失败，并显示错误提示。

在对话框输入：

> 根据上传需求生成场景和测试用例，包含评审，每个关键节点等我确认。

预期：

- 文字回复、成果附件都在 AI 气泡内，输入框仍保留在原位置。
- 任务实际把项目规则加入模型上下文时，聊天中出现引入数量及可展开清单；“查看/管理项目知识”打开同一知识库。
- 点开需求理解，在采用规则的条目旁看到“项目历史记忆”；文档引用显示“当前文档”。可继续展开具体引用。
- 这个清单表示“送入模型上下文”，不声称每条规则都被结果采用；成果标签表示条目确实引用了哪类来源。

### 3. 当前对话禁用规则，再用对话继续

需求理解等待确认时，打开“项目知识库”，关闭该规则的“本次对话使用”。返回对话，应出现重新理解的确认提示。

输入：

> 同意，按照本次知识库选择重新理解需求。

预期：

- 创建一次新的理解流程，旧成果保留供历史查看；新理解不会继承被禁用规则及旧成果中的假设。
- 停在新需求理解确认点；回复“同意，继续”后进入场景确认，再依次进入用例草稿、评审结果确认。
- 回到会话 A，规则仍然可用。B 的开关没有取消项目共享。
- 如果需保留该规则，再启用并按新的提示重新理解。

正在生成的步骤不允许同时切换规则；等到人工确认点再调整。旧成果依然可查看和导出；针对旧成果的解释会明确其历史依据，不将它重新用于新生成。取消共享与本会话禁用是不同操作。

### 4. 对话中添加用例字段

完成全部确认后，在聊天中输入：

> 给当前用例增加 test_data（测试数据）字段，根据已有需求填写测试输入；保留其他内容。

如 AI 给出修改预览，先查看并确认。若它同时提出了 Profile 列建议，直接查看该建议；若只改了用例数据，输入框上方会出现未配置导出字段提示。

点击“同步到 Profile · 查看更改”。预期：

- 聊天中出现这次操作与更改摘要。
- Profile 弹窗显示“+ 新增列”，新内容为绿色；当前 Profile 在确认前不变。
- 点击确认应用后，字段同步建议消失。同步只增加列配置，不重跑用例生成，也不改写已有字段值。

可以在弹窗中查看完整配置。当前版本按配置项勾选应用；`excel_columns` 作为一组确认，并非每个字符单独提交。

### 5. 演示细小差异和人工确认

在聊天框输入：

> 把用例导出列 test_data 的列名改为“登录测试数据”，并在写作规则里增加“步骤使用明确的动作动词”。先让我查看 Profile 更改。

点开建议中的“查看 Profile 更改”。预期：只突出变化的列或文字，删除为红色删除线，新增为绿色；其他列不整段重复铺开。可取消建议，也可勾选需要的配置项后确认。

### 6. 导出检查

打开“查看成果”，选择测试用例，点击“导出 Excel”。选择刚确认的当前 Profile，下载 XLSX，检查新列和数据。

要单独演示导出提示，可在第 4 步保存用例后暂不同步，先打开导出窗口：

- 选定当前 Profile 时，显示未配置的字段以及“补充到模板 · 查看更改”。
- 选择“生成时的配置快照”时，会提示哪些列未配置；快照不会被改写。选择当前 Profile 后可补充列。
- 可以按所选格式继续下载；提示明确列出本次会遗漏的字段。
- 导出所选行时，只检测这些行中的字段。存在模板必填缺项时仍需要先补全。
- 若同事同时更新 Profile，系统拒绝过期建议，点击“刷新字段建议”后重新查看即可，不自动提交新的更改。

## 回归观察点

- 需求理解、场景、用例草稿、评审各人工节点仍需分别确认；查看、解释、估算不会代替确认。
- 原有导出、历史成果、项目样例、模板学习保留。
- 字段检测排除内部标记、引用、关联 ID、步骤派生字段；保留 `0`、`false`、人工执行字段的空值。
- 历史成果的来源标签优先读取保存时的来源版本；没有可靠历史记录时显示来源待查看，不猜测来源类型。

## 验证范围

使用受控模型响应验证原生 Tool Calling、SQLite 和 LangGraph 的真实 HTTP 主流程，以及实际 XLSX 单元格。前端验证交互、差异渲染、导出范围、过期建议及知识开关，另执行 TypeScript 和生产构建。未连接你的内网/Azure 模型；未进行浏览器截图验收或运行全部历史测试。受控响应通过不代表任何模型的自然语言识别都必然成功。
